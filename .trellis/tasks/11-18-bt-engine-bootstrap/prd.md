# BT 搜索与下载引擎一键初始化

## Goal

当栖库缺少 BT 搜索或下载引擎时，用户在下载中心点击“初始化”，系统自动检测环境、拉取固定镜像、部署缺失组件并接入现有功能。界面清楚展示进度、配置待办和恢复动作，降低 NAS 首次使用成本。

## Scope of This Turn

用户已于2026-11-18确认按计划实现；本轮进入 Phase 2。授权使用指定 Linux 主机的 Docker TCP 服务进行隔离部署验收，测试后清理仅本任务创建的容器、镜像及临时资源。不得记录用户提供的凭据。

“自动拉取对应部署按照”按“自动拉取对应镜像并部署安装”理解。现有搜种、下载功能及其未提交代码均作为实现基础。

## Decision (ADR-lite)

**Context**：应用是非 root 的单服务，未持有 Docker socket；下载根和私密配置均在启动时固定。仅增加按钮不能获得宿主部署权限，也不能给运行中的应用补上下载卷。现有引擎离线不代表未安装。

**Recommended decision**：新增可选 `compose.engines.yaml`，首次启用时部署独立 `nas-engine-helper`，并预先接好下载目录、连接配置和 Unix socket。助手通过 Docker Engine HTTP API，仅按服务器内置模板部署 qBittorrent 与 Jackett；应用通过受控接口提交初始化任务并在线激活连接。已有 Prowlarr/Jackett/qB 继续走外部接入模式。

**Consequences**：用户首次仍需应用一次托管部署配置；完成后，缺失引擎的拉取、创建、启动和凭据衔接在页面完成，无需再手工复制来源 Key/下载密码或重启应用。助手是额外服务，持有 Docker 管理能力，必须把它明确当作受信任部署组件；接口白名单不是 Docker daemon 自身的权限隔离。

备选及一手资料见 `research/engine-bootstrap-options.md`。本方案已获用户实施确认。

## Requirements

### 1. 范围和兼容

- 首版目标是同一 Linux Docker 主机的 amd64/arm64 NAS；二进制运行、未接助手或其他架构显示原因及手动部署指引。
- 首版托管 qBittorrent 与 Jackett，不同时安装 Prowlarr；外接 Prowlarr 继续支持。
- 复用仓库已经固定的镜像版本和摘要。qB 保持 `5.2.4-1` 与现有磁力能力探针一致，Jackett 保持现有 LinuxServer 镜像模板；实施时重新校验模板和兼容性，不自动追随 latest。
- 每个模块支持 `disabled / external / managed`；兼容原环境变量，模式优先级和不合法组合有明确解释。
- 默认基础部署不运行助手或引擎，不连接 Docker，也不改变现有外接配置。

### 2. 检测与操作

- 下载中心提供“引擎管理”，搜索和下载分别显示状态；都缺失时显示“初始化缺失引擎”，单独缺失时允许只初始化相应组件。
- 只有助手成功读取 Docker 元数据并确认本安装的受管容器不存在，才显示“未安装”。单纯超时、拒绝连接、认证失败、助手失联均不能认定不存在。
- 已停止的受管容器显示“启动引擎”；外部实例故障只提供测试/修复连接引导；同名但不属于本安装的容器或非空未知配置目录显示冲突，不接管。
- 访问页面和 GET 状态接口没有部署副作用；只在用户明确点击后拉取或启动。

### 3. 初始化流程

- 流程为：环境检查 → 拉取固定镜像 → 准备持久目录 → 创建/复用受管容器 → 启动 → 凭据初始化 → 健康与版本检查 → 发布连接配置 → 应用自动接入。
- 新建下载器前按上游现有要求展示首次使用告知并记录用户确认，不替用户预填确认。
- qB 首选在全新空配置目录离线预置随机永久密码的固定版本哈希格式，启动后由实际生产适配器重新认证；实施前先验证准确配置格式。不能假设存在通用 `QBT_PASSWORD` 环境变量，不自动读取临时密码日志或关闭认证作为回退。凭据生成、写入与中断恢复必须复用同一份已持久化凭据。
- Jackett 启动后可取得自身 API Key，但不自动提供站点/账号。安装成功且未配置站点时显示“待配置来源”，不宣称搜种已就绪。
- 首版沿用回环管理入口和远程 SSH 指引完成站点配置，随后在栖库点“同步来源”自动接入单索引器，不手写 sources.json。管理页不得被当作通用反向代理嵌入栖库。
- 搜索来源最多八个；超过时让用户选择，不能静默丢弃；不推荐使用 Jackett `all` 聚合端点。不会自动执行真正的关键词站点搜索作为初始化步骤。
- 下载器就绪后仍须按原流程显式添加任务、确认内容类型和文件选集；初始化本身不添加 BT 载荷任务。

### 4. 进度、幂等与恢复

- 异步任务返回 ID，展示阶段、镜像层下载/解包进度、安全中文日志及明确错误；不编造全流程完成百分比。
- 刷新页面、关闭弹窗或浏览器断线不会取消服务端任务；重新打开能读取同一任务。
- 请求先持久化再执行；相同 requestId+相同目标返回原任务，不同目标返回冲突。不同 requestId 的重复点击也不能创建第二套同组件容器。
- 助手重启后按持久记录和容器所有权对账；已完成步骤不重复破坏，部分成功允许仅重试失败组件。
- 网络/拉取失败、空间不足、权限/端口冲突、健康/认证超时、应用接入失败分别展示恢复动作。保留已有配置、下载文件及任务，不自动删卷、重置或升级。
- 助手部署完成与应用连接可用分开判断；凭据文件发布并通过应用实际适配器探针后才显示连接成功。

### 5. 权限与资源边界

- 浏览器只调用栖库同源、管理员会话保护的接口；助手仅使用私有 Unix socket，不发布 HTTP 控制端口。
- Docker socket 只挂载给助手。助手只接受组件枚举与幂等键，不接受任意镜像、命令、容器JSON、宿主路径或 Docker API 代理请求。
- 镜像/网络/挂载/端口均来自受信任部署配置和内置固定模板，资源带安装ID与模板标签，恢复动作同时校验标签、镜像与挂载。
- 固定专用下载根在应用中只读、qB 中可写；仅 complete 子树可登记媒体库。Jackett 不挂下载卷，任一引擎不挂原媒体或应用SQLite。
- 私密配置通过独立只读目录、版本清单和原子发布提供给应用，不使用不可热替换的单文件 secret 掩盖更新需求；Key、密码、Cookie、临时密码日志不进入浏览器、事件或应用备份。
- 长时间镜像拉取不占媒体扫描队列、业务互斥锁或 SQLite 事务；不经过媒体 Range 数据通道。

## Acceptance Criteria for Implementation

- [x] 基础部署和旧 external 模式保持原行为，默认没有 Docker 请求。
- [x] 助手未接入、Docker不可用、实例不存在、已停止、认证失败、冲突、待配置来源有独立状态及正确动作；状态机/应用/UI分别覆盖。
- [ ] 全新环境一次操作部署两引擎的完整真实成功闭环仍待兼容宿主及可用仓库补验；固定模板、单组件及资源复用通过假Docker行为验收。
- [x] 用户可看到真实阶段与可用的层进度，刷新/重连能继续查看，无虚假百分比。
- [x] 重复点击、请求超时、助手重启以及创建/配置发布的不确定结果通过持久幂等和对账验收；不重复生成永久凭据。
- [x] 外部实例故障、未知同名容器、非空无主配置不被接管或重置。
- [x] qB 随机凭据热接入通过生产适配器+fixture，固定镜像永久密码首启/重启和真实内部网络生产适配器分别通过；未放宽版本与元数据停止保护。
- [x] Jackett未配站点待配置、最多8来源热同步由受控集成覆盖；固定镜像在设置管理密码后仍支持Key发现由诊断容器确认。真实已配置站点同步仍待补验，不算真实站点通过。
- [x] 安装完成与运行可用区分，助手失联不影响已可用的运行时和本地读取。
- [x] 搜索→确认→选集→原安全发布和五类入库回归通过，超大视频保持原 Range 流程。
- [x] 权限/磁盘/端口/拉取/认证失败按受控状态机脱敏并可重试；无任意 Docker 操作入口、无泄露原始密码日志。
- [x] 375/768/1024/1440宽度、明暗主题、键盘/关闭焦点/轮询竞态验证通过，手机底栏保持五项。
- [x] 状态机/应用/原流程集成通过；授权Linux上真实Docker/固定镜像首启和内部网络已执行并如实记录限制；全部本任务远程资源精确清理并核验。

实施结果与证据范围见`research/implementation-verification.md`和`docs/verification.md`。旧Docker的Jackett EPERM预检明确失败，未关闭产品安全策略；qB直接拉取及已有阿里云加速受限，未通过更换摘要规避。不得把诊断和fixture结果算作完整默认部署成功。

## Definition of Done

规划交付已完成；实施、独立检查、契约文档与资源清理已完成，任务进入review。兼容宿主上的完整真实成功闭环保留为明确验收缺口，不自动提交或归档。

实施交付：中文方法/实体字段/配置注释、显式类型、关键中文脱敏日志；通过格式、静态检查、构建、独立集成和原流程回归；更新部署/接口/备份/恢复文档。临时生成的单元测试文件执行后按 AGENTS.md 删除，保留可复用集成脚本。远程Docker测试必须先记录基线并给所有新资源加本任务专属标识，完成后仅清理本任务资源并核验；禁止自动提交或归档。

## Out of Scope

- 安装宿主 Docker、动态给运行容器增加挂载、多宿主机/远端daemon、Windows Docker引擎、Kubernetes/Podman兼容承诺。
- 自动升级、卸载、删除数据、通用容器面板、任意镜像/脚本执行、自动接管外部引擎。
- 自动赠送站点账号、绕过验证码、自动订阅/RSS、网页爬虫或 qB 可执行搜索插件。
- 本轮重做现有 UI 主题、媒体模型、扫描器和大视频播放器。

## Implementation Sequence

1. **部署基础与助手**：固定模板、预挂载、私有IPC、Docker适配、独立持久状态与幂等任务。
2. **引擎安装闭环**：两种引擎的拉取/启动/凭据/探针、重启恢复、受管资源复用与失败处理。
3. **应用接入与界面**：模式兼容、运行时激活、来源同步、状态API、初始化面板及进度恢复。
4. **回归与交付**：非Docker模拟/集成验收、原BT/搜种/五媒体与大文件协议回归，文档及用户实机清单。

详细边界、接口、数据模型、恢复矩阵和文件清单见 `info.md`。
