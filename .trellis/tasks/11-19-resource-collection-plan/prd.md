# NAS 资源收集功能修改计划

## Goal

根据关联聊天“推荐 NAS 音视频获取方式”的调研，为当前 NAS 内容管理系统规划从资源发现、订阅、获取到整理入库的功能闭环，明确现有能力复用、增量修改、实施顺序和验收条件。2026-11-20 用户已指令“按计划实现”，本轮实施已确定的多来源首期范围。

## 已知信息

- 用户希望基于 2026-11-19 的音视频获取搜索结论提出当前系统的修改计划。
- 关联聊天 ID：01a1f314-4388-7862-99e9-f5eeaed7cc76；先前调研保存在 `../11-19-plugin-market-fnos-plan/research/`。
- 既有插件、市场和飞牛兼容计划继续保留；本任务独立规划资源收集业务，后续明确双方依赖。
- 用户已选择“多种来源一起做”：首期覆盖多类资源入口，接受更大的开发和验证工作量；不能将首期收窄为仅影视动漫。

## 规划假设

- 以现有媒体管理和下载能力为基础，优先建立可独立交付的收集闭环。
- 用户已批准按本计划采用方案 A 实施，多来源首期范围保持。
- 宿主平台、真实来源凭据和外部服务部署在具体实施阶段核实。

## Requirements

### R1 首期覆盖与产品边界

- 首期包含影视/动漫 RSS 与 BT、网页音视频、自有音乐、本地和远程文件导入；允许分批开发，但这些入口全部通过验收才算首期完成。
- 建立统一的“资源收集”业务模块，覆盖来源配置、订阅规则、候选确认、获取任务、整理预览、媒体入库和失败处理。
- 下载器、索引器、订阅套件、整理器与播放器分别建模；来源可用、工具已连接和资源可获取分别显示。
- 资源来源和认证由用户配置，不预置可用片源、不把安装工具当作已拥有资源。

### R2 影视和动漫收集

- 手工 BT 搜索和选文件延用现有链路；增加来源到收集任务的关联和进度回显。
- 新增有界 RSS 拉取、条件请求、来源健康、条目持久化、增量去重及订阅调度。
- 规则支持关键词/排除词、内容类型、质量与大小约束、目标目录和选文件策略；只有明确开启且匹配无歧义的规则自动执行。
- 集数或作品匹配不明确时进入待确认；动漫绝对集数需显式映射，不能把标题文本猜测当成稳定作品标识。
- 订阅可暂停、恢复、试运行和手工补查；避免重复抓取、重复下载及重复入库。

### R3 网页音视频

- 提交受支持的 HTTP(S) 页面链接，预览标题、格式与输出类型，支持保存视频或提取音频。
- 通过受控获取执行端运行固定工具适配器；API 不接受任意 shell、命令参数或可执行文件路径。
- 首期以单链接单条目为边界，不自动递归播放列表或频道；批量粘贴先预览并按条目记录结果，限制条目数和空间预算，允许部分失败重试。
- 首期不提供通用 Cookie 上传和 DRM 处理；需登录或不支持的页面给出明确错误。

### R4 本地、远程和音乐导入

- 本地导入选择管理员配置的目录，先扫描/预览；已有媒体默认只读登记并扫描，需要归档副本时才复制至受管收集目录。本轮功能规划不额外引入浏览器媒体上传。
- 远程导入选择已配置连接和目录，预览后复制；首期采用非破坏性的复制语义，不提供删除式同步、挂载或双向同步。
- 自有音乐走相同导入链路，读取现有标签、封面和音频属性；音乐整理可预览目标目录，原文件标签保持不变。
- 音乐文件、视频文件、已存在媒体和不支持文件在预览中分别列出；重试不能把已有成功条目再复制一遍。

### R5 统一任务与入库

- 区分订阅条目、资源候选、作品/集数、获取任务、产出文件和媒体库记录；不把下载完成直接显示为入库完成。
- 执行任务和步骤均持久化，记录幂等键、执行归属、外部任务引用、状态、尝试次数及中文脱敏错误。
- 统一处理排队、运行、待确认、验证、发布、扫描、完成、失败和取消；具体适配器声明可恢复、可取消、可续传能力。
- 新下载/归档复制先写入隔离目录，校验路径、类型、大小、完整性和目标冲突，再原子发布并关联现有扫描结果；既有文件只读登记沿用已授权媒体扫描，不强制搬迁或重新发布。
- qB 做种数据、工具暂存目录、受管收集目录和媒体源目录职责明确；外部工具管理的任务只观察/导入，不自动取得控制权。
- 导入取消不删除原文件；取消正在做种的任务、清理下载数据和移除媒体条目分别表达操作意图。

### R6 页面与配置

- 新增资源收集入口，提供概览、来源、订阅、候选和任务；收集任务详情能跳转到现有下载或媒体详情。
- 来源配置区分 RSS/索引、网页获取、本地目录、远程存储和外部自动化，给出连接状态与能力说明。
- 设置中增加获取执行端、凭据引用、路径映射、限额及保留策略；每个参数都有中文解释，秘密不明文回显。
- 页面支持桌面与手机、两种主题、键盘操作、空状态、部分失败和断线恢复。

### R7 外部生态与插件计划协同

- 首期交付固定适配器及外部应用入口，插件市场与飞牛桥接不作为多来源收集的前置条件。
- MoviePilot / AutoBangumi 及 Sonarr / Radarr 等可作为既有外部服务登记和进入；通过专用完成目录导入已有结果。
- 深度 API 管理、远程安装、通用扩展市场和自动接管第三方任务作为后续阶段，不计入首期闭环。
- 连接外部自动化工具时选择唯一编排方及独立目录，不能让内建订阅与外部套件同时控制同一任务。

### R8 平台、可靠性和质量

- 平台能力按实际执行端和目录映射检测；不能把 Windows 上的不可用功能伪装为任务成功。
- 实施前修订与自动订阅、下载写入、媒体只读或固定助手权限相关的旧契约，增量迁移主库并保留历史记录。
- 对来源 URL、重定向、私网访问、路径穿越、链接文件和归属进行检查；NAS 私网服务通过显式来源策略允许。
- 限制并发、超时、单项大小、播放列表条目、暂存空间及失败重试，关键流程输出中文脱敏日志。
- 所有新增后台任务纳入现有服务生命周期和完整退出协议。

## Definition of Done

- 完成所有首期链路、代码检查与验证，记录真实覆盖和部署环境限制，任务按实际进度更新。
- 后续实施遵守中文方法、字段和配置注释、显式输入输出类型以及关键中文业务日志要求。
- 本地工具经 `python -B scripts/project_env.py -- ...` 执行；实施阶段生成的临时单元测试在任务结束时清理。

## Out of Scope

- 不连接或操作用户真实帐号与媒体；使用隔离样例验证开发结果，工具部署由显式配置决定。
- 首期不重做通用插件市场、飞牛 FPK 兼容、任意脚本执行、第三方任务自动接管和播放服务。
- 首期不引入 Usenet、自动字幕/全库刮削、复杂画质升级、音乐源搜索下载或付费平台资源解锁。
- 首期不提供云盘挂载、双向/删除式同步、不确定剧集的自动补集或原文件标签改写。
- 首期网页入口不递归播放列表/频道、不承诺所有站点或需登录内容可下载。

## Technical Approach

采用“系统内统一收集控制面 + 固定获取适配器 + 可选外部自动化工具”方案。具体字段、接口、目录、文件清单、阶段依赖与验证见 [info.md](info.md)。

## Decision（建议方案）

**用户已确认**：首期多来源覆盖，接受较大的开发与验证范围；2026-11-20 已授权按计划实施。

**A：统一收集模块和固定适配器（推荐）**：内建任务/订阅/去重/入库，复用已有 BT；网页与远程文件通过受控执行端获取，外部套件按独立来源协作。入口一致，可逐步交付，需承担任务恢复与执行端维护。

**B：以 MoviePilot 等外部套件为主，系统仅聚合入口和扫描**：影视较快接入，但网页/音乐/远程文件仍需独立工具，任务和失败处理分散。

**C：先完成通用插件平台再开发所有来源**：扩展面更广，但会把资源收集与市场、安装和宿主兼容绑定，首期交付周期明显增加。

**建议选择 A**，保留 B 的外部协作入口；C 继续按原插件计划独立推进。用户已批准按该方案编码实施。
