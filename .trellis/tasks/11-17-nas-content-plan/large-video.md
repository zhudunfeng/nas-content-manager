# 单个超大视频的针对性优化建议

## 目标与范围

用户明确要求优化单个超大视频。本文件将其提升为首版的独立性能场景，而非一般视频功能的附带能力。2026-11-17 已实现首版直放路径：鉴权 Range/HEAD、64 位大小与偏移、流连接上限、后台限流探测与封面、原生浏览器续播和退出清理。5 GiB 稀疏协议样本通过高位与尾部精确字节验证，另有真实 4 秒 H.264 MP4 播放/seek/续播验证；尚无真实超大影片和目标 NAS 的性能测量。下文转封装、HLS、硬件转码、图集与优化副本属于后续设计，不属于本次已交付能力。

默认沿用单镜像、单 Compose 服务和本机文件目录，目标是控制起播/拖动等待、保持应用内存有界、避免无意义的全片处理与缓存膨胀。视频体积、时长、平均/峰值码率、格式、浏览器能力、磁盘与网络条件分别影响体验，不能仅按 GB 数选择策略。

20/100/200GiB 可以作为后续样本规模的候选，不代表用户已确认的容量、不代表最大支持值，也不代表已经通过测试。

## 首选处理路径

1. 客户端支持所选视频/音频/字幕组合：直接播放原文件，支持鉴权后的 HTTP Range。
2. 编码可用但容器或部分音轨不兼容：按需要转封装，或仅处理不兼容音轨，不默认重编码视频。
3. 编码、带宽、烧录字幕或输出规格确实需要转换：受控启动转码，并按客户端能力选用 HLS 等输出。

以上是策略顺序，不是简单按文件扩展名判断。HLS 不是大文件播放的必需前置；Range 解决字节读取，不单独保证媒体解码或任意时间点精确定位。

## 原文件传输

- 视频存文件系统，数据库只存路径、版本与元数据。
- 使用打开的文件句柄与可随机定位的标准 HTTP 文件响应能力，优先采用 Go `net/http` 的 `ServeContent` 等原生实现，业务层先完成鉴权和目录边界校验。
- 大小、偏移和长度计算使用 64 位类型，检查传输头、数据库字段与前端展示的一致性。
- 正确处理 HEAD、完整请求、单范围、尾部范围与超范围请求；以 HTTP 的 206、416、Content-Range 等语义验收。
- 不使用全文件读入内存、Base64 或先下载完整视频再播放的链路；缓冲区大小与并发数量受控。
- 使用与实际表示版本一致的 Last-Modified/ETag 等验证信息；文件变化后不继续复用旧版本切片或缓存。不能把未验证的大小/时间摘要直接当作可靠的字节级身份。
- 已压缩视频默认不做响应动态压缩；代理、响应超时与缓冲配置不能妨碍长时间范围流传输。
- 客户端取消、拖动或退出时传播取消信号，释放过期请求。设定连接/并发与限流边界，不通过无限扩大缓冲掩盖吞吐不足。
- 在可用条件下利用操作系统高效文件传输；TLS、HTTP 协议和部署路径影响具体实现，不承诺所有场景均为零拷贝。

## 导入、元数据与封面

- 首次扫描仅做目录发现、stat 与必要的轻量登记，尽早让内容出现在媒体库中。
- 不要求计算整片哈希或完成全片缩略图后才允许浏览；完整校验作为显式、可暂停的后台任务。
- ffprobe、封面提取和索引增强使用独立任务，配置超时、探测预算和资源并发；预算不足时显示待处理/信息不完整，不误报格式损坏。
- 不把小探测预算当成万能值：索引在末尾或结构复杂的文件可能需要更多随机读，允许有界重试与人工重探测。
- 默认提取少量封面，进度条预览图集按需生成并设置数量/空间上限，避免每次拖动重复扫描整片。

## 容器索引与拖动

- MP4 的媒体索引位置会影响起播读取路径；支持尾部 Range，不能假定所有文件索引都在开头。
- `+faststart` 属于可选的文件布局优化，可能需要额外的完整文件写入与空间，不在导入时自动执行，不覆盖只读原片。
- 若需要优化副本，作为明确可见的后台任务执行，先做空间预算并记录源文件版本；副本不纳入无限期默认缓存。
- MKV 等格式的索引情况和关键帧分布也会影响拖动成本；缺少索引时允许展示正在准备，不虚构即时定位能力。
- 转码按目标时间附近的可用定位点启动，并处理关键帧对齐与精确度取舍；不能把字节偏移等同于时间，也不能承诺单靠任意 `-ss` 与流复制实现帧级精确。
- 前端合并快速连续拖动，仅保留最新定位意图；取消旧会话和无用准备任务，防止多次拖动并发生成整片转码。

## 按需转码、分片和缓存

- 按需启动受管理的 FFmpeg 进程，维护播放会话与进度，不在普通 API 请求中同步等待整片处理。
- 支持的转码输出按有限预取窗口生成；只有实现按时间重新启动的定位策略后，才能将生产速度限制在播放位置附近。
- 若采用持续 FFmpeg + HLS 的实现，要有生产节流、缓存保留与再次定位策略，不能仅删除已播片段就声称任意 VOD seek 仍然可用。
- 不预先转换整部超大视频，不默认生成所有清晰度；提供可选的离线优化任务时明确显示空间与耗时。
- 缓存按源文件版本、轨道、字幕、清晰度和处理配置隔离，防止错用过期结果；同一会话复用处理流程，不为每个切片无条件新建 FFmpeg。
- 为分片/缩略图/优化副本分别设置空间预算与清理策略；活跃会话的必要数据有保护，过期会话可回收。
- 剩余空间不足时停止新增衍生物并提示，不删除源视频；取消或失败后的临时文件可恢复清理。
- 转码并发初始保持保守且可配置；硬件加速在实际 NAS、驱动和格式样本上验证后开放，不承诺任意设备实时 4K/HDR。

## 用户界面

- 播放器显示“准备播放、正在缓冲、正在转换、暂不支持、存储离线”等可理解状态。
- 高级面板提供播放方式、选中轨道与可获得的码率/缓冲信息，不把未经验证的原因直接标成网络或硬盘故障。
- 支持继续播放、重试、切换可用播放方式与取消；不自动反复启动失败的高负载任务。
- 主动保存播放位置；退出后返回原内容位置，重连时从保存进度恢复，区别于只恢复一次 HTTP 字节请求。

## 最小首版与增强边界

首版必须具备：大文件正确登记、64 位流式 Range/HEAD、直放与拖动、进度恢复、取消传播、探测/封面资源限制、缓存和空间保护、明确错误状态。

按实际格式与网络需求增强：按需转封装/HLS/转码、硬件加速、索引优化副本与进度条预览图集。若真实样本依赖这些能力才能播放，则应调整到交付范围，而不是把不兼容文件标为已支持。

默认不因此新增 Nginx、Redis、MinIO 或专用转码服务，保持一个应用镜像和一个 Compose 服务；部署已有反向代理时单独检查 Range、缓冲、鉴权与超时行为。

## 建议验收矩阵

| 场景 | 验证内容 |
| --- | --- |
| 协议与超大偏移 | 大于 4GiB 的起始/中段/尾部读取，HEAD、无效范围、条件请求，返回字节与源文件匹配 |
| 起播与 seek | 真实大文件起播、跳到约 90% 位置、连续快速拖动、返回前一位置，记录延迟与失败情况 |
| 文件结构 | MP4 索引前/后、可用的 MKV 索引、长 GOP、不同音轨与字幕，明确支持与不支持组合 |
| 资源 | 记录应用与 FFmpeg 各自的峰值内存、CPU、存储读写、网络吞吐、缓存峰值；确认应用内存不随文件大小线性增长 |
| 网络与存储 | 本机磁盘、用户实际挂载方式、受限带宽与中断重连，验证状态与恢复行为 |
| 生命周期 | 关闭页面、切换视频、取消任务、应用重启、低剩余空间，验证请求/进程/缓存回收与原文件安全 |
| 并发与干扰 | 播放同时扫描和生成封面，确认普通内容浏览与受控播放会话仍可用 |

先登记测试硬件、系统、浏览器、文件编码/时长/峰值码率与网络条件，再制定起播/seek 的 p50/p95、内存和吞吐验收值。协议测试可以使用合适的合成文件，但不能用稀疏文件替代真实视频的解码、索引与性能验证。
