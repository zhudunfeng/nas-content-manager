## 2. 总体依赖与交付边界

- S05 作品模型是 S06 本地元数据归属的硬前置；两者都不要求先实现全量音乐、相册或图书专用模型。
- S07 的外挂字幕、技术轨道诊断只依赖现有 item，不硬依赖作品或刮削；可与 S05/S06 分别实施和验收。
- S08 的状态/标签筛选与小批量操作可在 S05 前实施；作品/年份筛选依赖 S05/S06，路径重关联应在 S05 关联结构固定后完成并回归相关引用。
- 生产数据迁移前需要父计划的数据备份/恢复基线；**可重建技术缓存**与**手工海报等用户资产**必须有不同备份策略。S06 发布用户上传功能的前提是备份恢复已覆盖用户资产清单与文件。
- 新 API 沿用现有会话鉴权、同源变更检查、严格 JSON、显式 DTO、中文错误和脱敏日志。新配置均有中文解释；后台任务有预算、取消、超时和重启语义。
- 关闭新功能只隐藏入口/暂停增强，旧 item 路由、列表、播放与进度仍可工作；这不等于旧二进制能读取升级后的数据库。跨版本降级要恢复匹配的备份快照。

## 3. S05：作品与季集模型（相对工作量 L）

### 范围与数据草案

首轮只做电影与电视剧的**逻辑组织**：作品详情、季/集导航、同一作品的多个文件版本、人工归组和拆分；保持五类媒体平铺浏览作为未归组与其他类型的回退。不要重命名或移动原文件，不根据相同片名自动合并。

拟议新增：

- `media_works`：作品 ID、kind（movie/series）、最小标题、revision、创建/更新时间；稳定 ID 与 items.id 分离。
- `media_seasons` / `media_episodes`：series work_id、显式季号/集号、revision；季号 0 为特别篇；缺失或无法判断集号保留未匹配状态，不猜测。
- `media_work_items`：电影作品与 item 的版本关联，item 仍是文件播放和个人状态的身份。
- `media_episode_items`：episode 与 item 的多对多关联，允许同一文件覆盖多个明确的剧集；不通过把 items 复制成多个虚假文件实现多集。
- 外部 provider ID 作为来源明确的关联字段/独立表，不把 TMDB 数字当本地主键，不因同名就认为是同一作品。详细简介、年份、海报、字段来源与锁由 S06 承接。

拟议 API：

- `GET /api/works`、`GET /api/works/{id}`：分页作品及季集/版本结构；不一次返回整库所有文件。
- `POST /api/works`、`PATCH /api/works/{id}`：人工创建/改最小结构，输入 revision 避免覆盖别人或旧页面的更改。
- `POST /api/works/{id}/items/preview` 与 `POST /api/works/{id}/items/apply`：返回关联冲突/多集计划，apply 只接受不透明计划 ID、原 requestId 和 revision；有歧义需要确认。
- `GET /api/items` 和单项 DTO 保持兼容，只增可空 work 摘要；旧 ReaderDialog 始终通过 item_id 播放，不重绑定进度到 work_id。

### 小 PR 顺序

1. **S05.1 数据与兼容骨架**：新表、typed DTO、读 API、旧库迁移夹具；迁移只建空结构，不在启动时对全库做猜测归组。支持无关联旧 item 的原样列表和播放。
2. **S05.2 显式归组**：人工创建作品、选择已有 item、季集与版本预览/提交、拆分/取消关联；新增持久修订和计划过期检查。只添加关系，不删除 item。
3. **S05.3 Vue 作品体验**：保留文件视图，增加作品视图、详情与季集/版本选项；选定具体文件后复用现 ReaderDialog。可选后台候选归组只给建议，不自动接受模糊片名。

### 入口与验收

- 修改入口：`store.go/models.go/items.go/server.go/jobs.go`、`web/src/types.ts/App.vue/MediaCard.vue`；拟议新文件 `internal/app/media_catalog*.go`、`web/src/components/WorkDetailDialog.vue`。
- 验收：旧库 items ID、收藏/标签/进度、下载和收集引用逐一不变；电影多版本、S00 特别篇、多集文件与未知集号；拆组再重组不清空用户状态；旧请求 revision 冲突；扫描失败不破坏关系；375/768/1024/1440 和双主题。
- 回退：关闭作品视图并继续旧文件视图；删除作品或关系只删逻辑组织，不级联删除 items 或原文件。回滚到旧版本使用迁移前配套快照，不强行降低 PRAGMA。

## 4. S06：本地元数据、NFO/海报与字段锁（相对工作量 L）

### 范围与来源规则

依赖 S05；首轮读取本地 NFO/本地海报、展示简介/年份/海报、人工纠错和字段锁。暂不接新的在线 provider，不写回媒体目录。MoviePilot 继续只负责外部操作，外部“刮削完成”不会直接伪装成本库元数据更新，需在本地可读路径执行刷新。

拟议模型与合并语义：

- `media_metadata_values`：目标类型/ID、字段、来源（filename/nfo/manual 等受控枚举）、value_json、来源版本；技术参数与用户内容元数据分开。
- `media_metadata_overrides`：目标、字段、手工值、locked、revision；显式清空用明确的空值表示，不能把空值误认成“没有覆盖，重新落回 NFO”。
- 手工编辑默认锁定字段；锁定值优先且任何扫描/刷新不覆盖；其他字段可独立接受新 NFO。解除锁不立即清空手工值，下一次刷新预览明确显示拟替换的差异，确认后才应用。变更冲突返回 409。
- `media_assets`：用户上传/手工选定海报的稳定资产 ID、所有权、类型、摘要和原始文件引用；原件保存在专用用户资产目录，缩略版本仍进入可重建缓存。原件与清单必须纳入备份/恢复。
- 来源文件版本（路径、大小、mtime 与可选有界摘要）和 metadata revision 控制重扫/并发；刷新未改变来源时不得重复覆盖字段，也不能把 size+mtime 宣称为内容强哈希。

拟议 API：`GET /api/works/{id}/metadata`、`PATCH /api/works/{id}/metadata`、`POST /api/works/{id}/metadata/refresh-preview`、`POST /api/works/{id}/metadata/refresh-apply`、受限海报上传/选择与鉴权资产读取。Item 级元数据仅为未归组文件保留，关联变化时需要明确字段归属，不自动从一个版本的 NFO 覆盖整部作品。

### 小 PR 顺序

1. **S06.1 安全本地读取与候选**：NFO 候选定位、流式 XML/字段长度预算、受控栅格封面读取、解析结果及来源，不自动覆盖；失败只影响增强，不影响原文件浏览。
2. **S06.2 合并与字段锁**：解析值、手工值、锁与 diff 预览/事务提交、来源修订、锁/解锁验收；扩展后台显式 job 分派，保留取消/重启和幂等边界。
3. **S06.3 编辑与资产闭环**：详情编辑、来源/锁状态、刷新差异确认、手工海报、缓存失效；用户资产与备份任务联调后才开放上传入口。

### 安全预算草案（实施时写入可执行契约）

- NFO 首轮上限 1 MiB、XML 深度 32、总节点 20000、单文本字段 64 KiB；这是拟议资源限制，防止一个 sidecar 占满内存。XML 不展开外部实体，不读取外部 DTD，不执行 URL/脚本，不拉取 NFO 内远程海报地址。
- 候选只来自已授权媒体项的明确相邻命名（同名 `.nfo`、已确认的 movie/tvshow/episode 文件），根、symlink、大小和下载发布门禁均要通过；不得只因媒体项可播放便认为同目录所有 sidecar 都已发布。
- 海报只接受已验证的 JPEG/PNG/WebP 等受控栅格，原始上传草案 10 MiB、解码像素草案 40M；先读头预算后解码，不接受 SVG/HTML、任意路径或远程 URL。
- NFO 内文本按普通文本渲染；不得通过 `v-html` 展示源描述。日志记目标 ID/来源/结果，不输出原始 NFO/私密根目录。

### 验收和回退

- 样本：合法电影/剧集、坏 XML、超深/超量、无匹配/多候选、外链海报、越界软链、未发布 sidecar；仅部分字段变化；重扫十次不重复写无差异数据。
- 手工标题/空简介/海报被锁后重扫、外部刮削和重启均不覆盖；解锁后只在明确差异确认后替换；旧 revision 和过期计划被拒绝。
- 不修改源媒体及 NFO；测试手工资产备份恢复后仍可用、清理缓存后缩略图可重建；重启/取消任务不能把部分结果当整轮成功。
- 回退关闭元数据增强，展示文件名与技术封面；保留用户覆盖和原始资产，不能把它们当缓存删掉。停止导入来源值不自动清除用户值。

## 5. S07：受控外挂字幕与播放诊断（相对工作量 M）

### 首轮范围与拟议接口

不依赖 S05/S06，仅围绕现有 item；支持明确授权的本地 SRT/VTT 外挂字幕、字幕开关和语言选择、后端音视频编码/音轨信息、浏览器兼容性诊断。首轮不承诺内嵌字幕提取、音轨切换、音频转码或视频转码。

- 拟议 `GET /api/items/{id}/playback`：返回媒体源版本、已有诊断、探测状态、可用字幕 ID 与语言、轨道摘要和真实能力标识；GET 不启动无限制外部处理。
- 拟议 `POST /api/items/{id}/probe`：明确触发/复用持久有界探测任务；元数据变化后旧结果标记过期，保留原文件直放可用。
- 拟议 `GET /api/items/{id}/subtitles/{subtitleId}`：根据服务器记录的 ID 返回重新生成的纯净 VTT；客户端不能传任意 path 或 URL。字幕仍经登录、item 可访问性、库根和发布门禁。
- 拟议 `media_playback_probes` / `media_subtitles` 存源版本、字幕定位/语言和缓存状态；纯转化结果为可重建衍生物。相邻字幕输入本身属于只读媒体，手工上传字幕若后续加入则属于用户资产，需要备份。

### 小 PR 顺序

1. **S07.1 源诊断**：扩展现 FFprobe 受限字段（codec/profile/container/audio/video/subtitle stream/language），有限轨道数与输出预算；typed 状态和错误；区分“扫描支持”“浏览器可能播放”“实际播放成功”，不能以 canPlayType 的 maybe 当保证。
2. **S07.2 安全字幕通道**：服务端候选命名/语言解析、严格 SRT/VTT 读取与规范化、有限转换缓存、鉴权 VTT；未通过发布门禁的 BT 字幕不开放，明确提示未授权/未导入。
3. **S07.3 Reader 集成**：video 内受控 track、字幕开关/语言与错误恢复、诊断面板；保留按需 Range、已有进度恢复和关闭释放，不引入全片 Blob 或新播放器生命周期。

### 字幕安全预算与门禁

- 草案输入文件上限 8 MiB、最多 100000 cue、单行上限 64 KiB、总规范化文字上限 4 MiB；时间戳必须有限、非负、结束不早于开始，最大时间草案 7 天，超过给出中文限额提示而非静默截断。
- UTF-8 为默认；需要 GB18030 时使用已存在的受控编码能力并明确选择；不让浏览器下载/猜测无界字幕。
- VTT 重新生成时间和纯文本 payload，去除/拒绝源 STYLE/REGION、HTML/脚本/资源引用等非必要内容；不把输入 VTT 原文直通，不将字幕内容渲染到应用 DOM 的 HTML。
- 输出 `text/vtt; charset=utf-8`、nosniff、private 缓存；缓存键包括字幕源版本及规范化版本，过期与取消不发布半成品。
- 首版优先正常只读媒体库。对于下载/收集目录，必须复用或显式扩展原发布清单；**禁止为了读字幕把 `checkDownloadPath` 改成“同目录即允许”**。若选中字幕的发布能力未形成闭环，就保留不可用状态而不是绕过门禁。
- 服务端读取超时、转换并发和解压无关的内存预算有界；故障只禁用字幕，不切断原片播放或覆盖进度。

### 验收、后续条件任务与回退

- 字幕样本：中文/多语言、SRT/VTT、坏时间、超长 cue、超量、STYLE/脚本、软链与路径穿越、无会话、未发布下载、改文件后的缓存失效；视频有/无字幕与关闭后释放。
- 探测缺 FFprobe/超时/坏文件/32 条轨道预算上限时显示真实降级；不得给全库同步探测阻塞初扫；原有 5GiB Range 协议与真实影片回归分别记录。
- 条件任务（不纳入本轮）：在目标设备测得具体失败样本后，先流复制转封装，再考虑仅音频转码；另立输出空间、会话、并发、鉴权、清理、崩溃恢复和资源限制契约。硬件视频转码继续后置，不能因为有 FFmpeg 就算方案完整。
- 回退关字幕/诊断入口并清理可重建 VTT 缓存，保留原文件直放与旧 progress；不改变源字幕或原媒体。

## 6. S08：筛选、批量状态与文件重新关联（相对工作量 L，可拆分）

### 首轮范围与拟议数据/API

- 扩展 `GET /api/items`：消费状态、missing、标签精确包含/组合、大小/时长/分辨率范围；字段有界校验和白名单排序。work/year 等依赖作品与元数据后追加。
- 不以修改 position 为“标记已看”；拟议用户媒体状态增加明确 consumed_state/override，保留真实进度；默认状态可从进度派生，手工“未看/已看”不伪造时长或页数。
- 拟议 `POST /api/items/batch`：首轮最多显式 200 个 item ID，固定动作（add/remove tags、favorite、set consumption state）；同一 requestId 对不同参数返回冲突；只改应用数据库，不提供批量删源文件。
- 小批量纯数据库操作采用短事务和 revision 检查；首轮采用全有或全无，冲突返回哪些 ID 需刷新。不要在事务内探测文件；不需要为最多 200 个轻操作创建一个运行线程/每项 goroutine。
- 若借父计划新增通用操作记录存 requestId/结果，应明确该依赖；否则在本任务建立有界结果记录。不要把非收集操作写进 `collection_*` 表或假定现有 jobs 能存任意批量 payload。
- 拟议 `POST /api/items/{id}/relink-preview` 与 `/relink-apply`：旧 item ID 不变，目标只能是配置内同类型库的已授权只读文件；预览记录旧路径/目标版本/依赖引用，apply 再校验存在性、源版本和 revision。只更新索引关联，不移动/复制/删除任何源文件。

### 重新关联首轮必须收敛的边界

1. 仅手工处理**旧文件已失联**的 item；不能拿“重新关联”悄悄替换一个仍可读文件的内容，不能仅按相同 basename/size 自动匹配。
2. 预览前后都检查媒体根、下载发布授权、实际文件类型和有限技术校验；不因人选了路径就绕过 staging/未发布门禁。不自动修改下载/收集发布清单来迎合新路径。
3. 首轮只允许目标尚未被另一个 item 占用。已被扫描成新 item 的目标返回明确冲突，保留两个记录及其所有引用；**不承诺首轮自动合并两个含状态的 item**。
4. 关联成功保留旧 item.id，保留收藏/标签/进度与作品关联；文件版本变化后清理/重建技术缓存、字幕与 metadata 来源引用，不删除手工锁定值，明确提示“原进度已保留，版本变化可能需校对”。
5. 核对进行中的 scan/enrich、download/collection 导入和相关锁；有活跃引用或目标变更返回冲突/稍后重试，不在一半文件操作后返回成功。文件验证完成后再开短事务，事务内用源/目标修订复查。
6. 完整重复项合并（多用户状态冲突、任务外键、发布清单、作品、手工资产与历史审计）另立条件任务；可先给只读重复候选，不自动删/合并。可选后台指纹有资源预算，不对初扫全片强哈希。

### 小 PR 顺序

1. **S08.1 查询与状态**：扩展列表 DTO/SQL、明确消费状态、索引与分页一致性；先保留既有 LIKE 查询，基于真实大库数据再决定全文索引，不凭空增加搜索服务。
2. **S08.2 小批量 UI/API**：明确勾选当前项、最多 200、显示数量/动作预览、固定 requestId、短事务和冲突提示；不做隐式“当前过滤全部十万项”。用户标签空值/重复/移除幂等，网络重试不重复操作。
3. **S08.3 重新关联**：手动定位、只读验证、计划/修订/门禁、应用时保留身份与重建衍生物；已索引目标冲突路径有清晰中文操作说明。
4. **S08.4 依赖增强**：在 S05/S06 稳定后增加作品/年份筛选和手工元数据的批量选定字段；大批量/全过滤结果选择只在另有持久快照、取消、进度与恢复方案时扩展。

### 入口、验收和回退

- 入口：`items.go/models.go/store.go/jobs.go/libraries.go/media.go/download_gate.go`，关联检查还需覆盖 `download_import.go/collection_import.go/collection_store.go` 的实际引用；拟议新 `internal/app/media_batch.go/media_relink.go`，前端 `App.vue/types.ts` 及小型批量工具栏/重新关联弹窗。
- 查询验收：组合筛选、未知时长/分辨率、未看/已看手工覆盖、UTF-8 标签、missing 状态、分页稳定性；受控大库记录真实时延和 SQL 计划，不将行数多就等同于已通过性能验收。
- 批量验收：0/1/200/201 个 ID、重复/不存在 ID、过期 revision、一次失败全回滚、重发相同 requestId、同 ID 改参数、并发单项编辑；不会覆盖未选字段。
- 关联验收：Windows/Linux 路径、同/跨库同类型、大小/mtime 改变、目标已有 item、源仍存在、越界/软链/未发布文件、活动扫描/导入冲突、预览后文件被替换；成功后旧 ID 和用户状态逐项比对。
- 回退：隐藏高级入口，旧单项操作和列表仍可用；消费状态及操作记录保留。已完成 relink 的回退是新的反向预览/授权操作，不能简单恢复旧路径值假装文件仍在；数据库版本降级按快照恢复。

## 7. 实施时需要同步的验证与契约

- 实施各 PR 前重新跑 CodeGraph 查询与当前 git/schema 检查，以实际头版本确定迁移；修订 `docs/api.md`、typed DTO 和对应真实 spec，不能提前把本设计写成“已实现”。
- 复用集成验证脚本风格增加受控媒体目录、真实 HTTP 和迁移夹具；临时单测执行后按 AGENTS 清除，保留集成脚本和结果。所有命令经 `python -B scripts/project_env.py -- ...`。
- 每阶段 gofmt/vet/test/build、前端 typecheck/build，加对应真实 API/浏览器场景；单元测试类为空不能作为行为验收。跨层媒体播放、下载/收集引用、取消/恢复要回归。
- 真实 Windows/Linux/NAS 上字幕编码、浏览器解码和大库/真实大影片表现单独验收。代码可独立交付，但缺少目标设备结果时不得宣称硬件能力已满足。

## Caveats / Not Found

- 全部新增模型/API/预算是建议契约，需实施任务在当前 schema 和实际样本上确认，不是已存在实现。
- 同目录 sidecar 的授权与下载发布清单是 S06/S07 实施最容易漏掉的跨层边界；无法安全授权时先降级不可用。
- 作品关系与手工元数据不能以替换 items.id 换取设计简单；“恢复旧界面”与“旧二进制数据库兼容”必须分开。
- 自动重复项合并、全库全文检索、硬件转码和所有媒体专用模型均不纳入 S05–S08 首轮。
