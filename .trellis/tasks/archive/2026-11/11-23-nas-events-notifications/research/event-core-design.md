# S04.1 持久事件核心研究设计

日期：2026-11-23。阶段：Trellis Phase 1.2。**本文件是实施建议，尚未实施或验收；表、类型和方法名均为拟议。**

本轮仅研究事件核心及已有生产者的接缝，未修改业务代码、迁移、正式 spec、PRD、任务状态或 `.current-task`，未启动实例、Docker 或真实外部服务。S04 目前只有 PRD，没有 `info.md`；应在正式实施前把选定契约写入该任务的实施设计。

## 1. 建议结论和交付边界

采用“有界事件历史 + 原业务行上的固定生产水位 + 短事务 typed helper”。每次故障 episode 有稳定事件 ID；生产事实的重复提交不增加次数；不同故障观察可累计；恢复关闭原 episode，再次失败建立新 episode。删除历史不能删除仍存活来源的去重水位，否则持续故障会在保留清理后重新刷成未读。

S04.1 可以先独立完成核心、迁移、事务助手、安全 DTO 和读标记存储助手，再以一个已有 collection 本地域状态接入证明契约。不等待 S02 账号或 S03 备份联调，也不依赖尚未存在的 `backup_runs`。如果生产者接入需要更宽的事实版本改造，应独立小切片，不能让事件核心反向等待。

| 切片 | 本研究推荐范围 |
| --- | --- |
| S04.1 | 增量迁移、事件注册表、episode/去重水位、原子本地域写助手、保留、严格安全 DTO/有界查询及确认助手；先接新发生的收集失败/待确认状态路径。 |
| S04.2 | 正式 events/read 等 HTTP 契约、鉴权与严格参数解析、未读中心、计数/处理/跳转及浏览器验收。S04.1 的内部读助手不等于已开放 API。 |
| S04.3 | 私密通道快照、网络 outbox、领取/重试/限额、安全 HTTP 客户端及投递生命周期。S04.1 不建投递表、不做任何网络通知。 |
| S04.4 | 持续离线阈值、有限磁盘事实、S03 实际备份结果、S02 账号动作等接入和恢复策略；各来源先交付自己的正确事实。 |

S04.1 不解析旧日志、不承诺补齐历史故障时间线，不把统一事件当作不可丢失审计。旧 collection 阶段历史继续保留原用途。升级前已终止且没有再次被可靠观察的旧故障，不自动冒充升级后新故障；如需历史回填，必须单列有界、可重放且标明“首次发现时间”的任务。

## 3. 最小持久结构

### 3.1 `system_events`：可删除的历史

建议字段如下，实际 SQL 必须有 NOT NULL、枚举/非负 CHECK 和必要的唯一索引。字段在 Go 实体、迁移说明中都要有中文解释。

| 字段 | 类型/约束与用途 |
| --- | --- |
| `seq` | SQLite 自增整数主键，仅作稳定顺序/游标水位；历史删除后不得复用。 |
| `id` | 独立随机公开事件 ID，建议 32 位小写十六进制；唯一，不由秘密或 bearer 派生。 |
| `source_kind`、`source_id`、`family` | 注册的来源种类、规范化且生命周期内不可复用的本地公开身份、固定故障族；不是 URL、路径或用户自由文本。 |
| `episode` | 正整数；同一来源/故障族的持久代次。 |
| `code`、`severity` | 固定注册代码及由目录映射的级别；不允许生产者传入任意摘要/metadata。 |
| `first_seen_ms`、`last_seen_ms` | Unix 毫秒整数；表示事件中心首次/最近接纳可靠观察的时间，不冒充真实远端故障起点。 |
| `resolved_at_ms` | 可空；来源事实确认解除的时间。用户点“已处理”不能写该字段。 |
| `occurrence_count`、`occurrence_capped` | 已接纳的不同失败观察数，初始 1；重放不增，安全饱和；布尔标识说明曾尝试超过上限。 |
| `attention_version` | 初始 1；只有新建或目录明确规定的有意义类别/级别变化才推进。 |
| `read_version`、`read_at_ms` | 已确认阅读的版本及最近确认时间；初始 0/null。 |
| `handled_version`、`handled_at_ms` | 已人工处理的版本及最近确认时间；与业务恢复、阅读分别存储。 |

唯一业务键是 **`UNIQUE(source_kind, source_id, family, episode)`**，不能用“错误文本 + 某分钟”、lastSeen、请求到达时间或一段日志哈希代替。公开事件 ID 与该业务键不是同一概念。

除 ID/业务键唯一索引，按实际查询增加必要索引：seq 倒序使用主键；保留按 first_seen/seq；若增加未读筛选索引，须用 EXPLAIN 确认有益，不为每个 DTO 字段机械建索引。事件不向来源行做 ON DELETE CASCADE，删除来源不应静默删掉其历史。

### 3.2 `system_event_meta`：唯一元数据行

固定 `id=1`，存实际删除的事件行总数、删除时仍未读的行总数、最近清理时间和计数饱和标识。截断计数与删行同事务提交，重复清理不能重复计数。优先清已读可能留下 seq 间隙，不能把“最大删除 seq”解释成此前全部历史都不存在。

元数据计数也有类型/上限；不是无界 tombstone/receipt 表。没有来源秘密、私密引用或任意 JSON。

### 3.3 生产水位随原业务行保存

每个已接入的固定故障族，在其原有业务行保存一个固定结构：`event_seen_revision`、`event_episode`、`event_open`、`event_current_id`。它们与来源事实一起读取、CAS 更新、提交；来源正常删除时随来源生命周期结束。一个来源若确实需要多个独立故障族，必须显式设计有限槽位，不能建立无限增长的自由字符串 map。

- `event_seen_revision`：最后已投影的可靠事实版本，不是时间戳。
- `event_episode`：已分配代次，0 表示尚未建立故障 episode。
- `event_open`：该故障族是否仍未被业务事实确认解除。
- `event_current_id`：最近一代公开事件 ID；即使历史已截断也保留，用来证明该代已经处理过。

这些标记不能通过查询“现存最后一条事件”重建，也不能在历史清理时清零。来源本身若没有可靠事实版本，应先增加明确的持久事实编号；不能为了接事件把下载用户 revision、job.updated_at 或错误内容冒充事实号。

来源身份不得在删除后复用。collection 的新来源/任务沿用其新随机身份；固定组件单例关闭/重启保留原水位。若某模块只能提供会复用的数字槽位，须先增加独立持久 incarnation，纳入来源业务身份再接入，不能让新来源 episode=1 与保留中的旧行冲突。action 的可跳转 targetId 与去重来源身份可以不同，但都须使用受限类型。

这使事件额外历史有界，水位空间随原本必须保留的业务实体数量增长，而不随重复故障次数增长；它不宣称整个来源库已经有界。来源归档/删除由原业务政策负责，不能为清事件顺带删媒体或来源记录。

### 3.4 迁移门禁

不在本研究分配 schema 6 或任何未来编号。正式实施时读取 S03 实际合并头，再安排唯一的下一增量；保持原迁移和现有业务 ID。S04.1 若升级 schema，必须同片审查离线账号维护的显式支持集、受限结构检查和历史版本夹具，不能仅推进正常启动常量便自动放行离线改密。

## 4. Episode、次数、未读与处理语义

| 输入/操作 | 事件行 | 水位/计数 | 阅读/处理 |
| --- | --- | --- | --- |
| 初始健康事实 | 不建事件 | 推进 seen revision，保持 closed | 无变化 |
| closed → 失败/待确认 | 新 episode、新 ID | episode+1，open=true，count=1 | attention=1，read/handled=0，未读且未处理 |
| 相同或更旧事实版本重放 | 不变 | 不增加次数、不分配新代次 | 不重新未读 |
| open + 新版本同类失败 | 更新同一行 lastSeen | count 仅加 1，不按 revision 差值加 | 普通重复不推进 attention，已读不会被探测刷回未读 |
| open + 目录定义的重要类别变化 | 更新同一行 code/级别 | 接纳一次观察，保留同一 episode | attention+1，原确认版本保留，重新出现待关注 |
| open → 确认恢复 | 原行写 resolvedAt | open=false，推进 seen；不增加失败次数 | 不自动标已读/已处理，默认不重新制造未读 |
| 恢复后再次失败 | 新行、新 ID | episode+1；旧行保持关闭 | 新行未读；不覆盖旧确认记录 |
| 用户已读/已处理 | 只推进各自确认版本 | 不改 episode/open/count | 两种确认互不冒充，也不表示来源成功 |
| 清理后同一 open episode 再观察 | **不重建已删除行** | 仍推进来源 seen；保持同代/原 ID | 不产生新未读；界面说明历史会被截断，当前事实看原业务页 |
| 来源被删除 | 历史在保留期内继续存在 | 水位随原来源删除 | 动作不可用；不伪造 recovered |

S04.1 用原 episode 的 resolvedAt 表示解除，不另造一个“新故障”来表达恢复。未来如发送恢复通知，应从该状态变化生成独立投递快照，不能因此重置故障去重。

“已读”定义为 `read_version >= attention_version`，“已处理”同理。确认时携带用户实际看见的 attentionVersion；迟到的旧确认只能确认旧版本，不能吞掉后来升级。请求版本大于当前版本必须拒绝，不能把未来版本预先标记。并发确认取最大已合法确认版本，不允许倒退。

## 5. Typed 短事务接口与失败策略

以下只是内部方法职责，不是本轮新源码。未来所有方法、实体字段、配置参数必须有中文注释，具名入参/出参有显式类型。

| 拟议方法 | 合同 |
| --- | --- |
| `observeEventTx(ctx, tx, source, marker, observation) (mutation, error)` | 只使用传入 `*sql.Tx`；source/code/family 为受限类型；observation 含可靠事实版本、失败或解除事实及可信应用时间，不接收任意 message/map。返回新 marker 和 created/updated/noop/truncated 结果。 |
| `listSystemEvents(ctx, db, query) (page, error)` | 有界 keyset 查询，安全 DTO；不经事件反向调用原业务写操作。 |
| `markSystemEventsTx(ctx, tx, confirmations) (result, error)` | 最多 100 个显式 ID/版本，严格去重、类型/范围核验；短事务更新读/处理版本；不存在/已截断 ID 不重建事件。 |
| `pruneSystemEventsTx(ctx, tx, now) (result, error)` | 删除到期/超限历史并原子更新截断计数；不动来源标记和来源事实。 |

本地域接入顺序：Tx 内读真实来源行/水位 → 校验当前业务 CAS → 计算本次实际事实版本和 typed observation → 写业务事实、事件及新水位 → 检查受影响行数/取消 → Commit → 才输出成功中文日志。任一写失败都回滚；CAS 零行不能留下孤立事件。可以先写事件再写来源或反之，但必须同一 Tx，不能拿事务外内存快照覆盖来源新水位。

单连接特别约束：助手不得在持有 Tx/Rows 时再调用 `a.db` 的读写；不得把会这样做的回调传给核心；不能吞掉 `RowsAffected`/Commit 错误。业务 mutex 的持有范围不得因事件扩展到网络/文件操作。提交错误或响应丢失时重新读取持久事实/水位核对，不凭内存重新分配 episode，更不能重发远端写。

### 跨资源结果与事件之间

远端调用、文件复制、快照发布都在事件事务外。已经记录的不可变意图/receipt/unknown 事实仍是权威；事件不是业务重试许可。

对一个尚未接入的跨资源来源，只能在它已经提供稳定结果 ID、明确事实版本及可重放本地结果后，选择：在同一结果事务接事件；或“先可靠保存结果，再独立短事务读取该结果并原子写事件+投影水位”，用有界本地对账修复两步间崩溃。后者只重放投影，绝不重放网络写。若来源只有可覆盖的当前状态，不能声称补齐所有中间 episode；必须先补足持久结果契约，或明确仅当前状态收敛的边界再接入。

**不推荐**遇事件错误后笼统忽略并报业务成功；也不能为了事件原子性，回滚/丢失一个已经执行的外部动作证明，再让旧状态机把它当新请求。S04.1 应先实现可证明的本地域原子生产者；直接改造 `collectionExternalFinish`、backup 或离线账号恢复的失败政策，须在对应联调片单独冻结。

核心写失败只输出固定中文诊断和公开来源 ID/受控错误分类，不输出原 SQL、输入参数或底层异常原文。不能为了报告“事件系统失败”再递归写事件，不能每次失败派生一个 goroutine。

## 6. 保留、资源上限与时钟

推荐固定首版政策：历史可见窗口 90 天、物理行数最多 10000；由常量集中定义并有中文解释，暂不扩展配置 UI。时间按 firstSeen 计龄，不能靠不断刷新 lastSeen 永久保留一个 open/未读 episode。

1. 清理先删除到期行，**包括未读/未处理和 open 行**。
2. 超过 10000 时优先删最旧已读行，再删最旧剩余行，使用 firstSeen/seq 稳定排序。
3. 删除实际命中的行数/其中未读数，与 metadata 在同一事务累计。硬行数上限在接纳新事件的事务内保持；查询不能把未读当无界保留例外。
4. 正常迁移完成、业务执行器启动前清理一次，运行中使用一个受 app ctx/wg 管理的低频维护器（建议 60 秒），事件写入时也维护上限；每次工作最多面对约 10001 行，不逐事件开后台任务。若后续改为分批清理，必须同时说明可见和物理保留的延迟，不能偷偷放宽上限。
5. 对安静运行的实例，物理年龄清理可滞后一个维护周期；S04.2 读助手按同一次 asOf 排除已经到期的行。停服期间不声称会有后台删除，下一次开库再清理。
6. 清理失败要有固定中文日志，不能静默称策略已满足；新建事件若会突破行数硬限，事务失败。既有事件更新是否可继续，必须确认没有新增行且不放宽 DTO 可见窗口。

计数/episode/version/seq 都做显式溢出检查。episode/version/seq 无法推进时拒绝本次投影，不回绕为旧 ID；次数/截断总数可饱和并展示 capped 标志。一个时间值只用于该事务，存储 Unix 毫秒；公共输出统一 UTC 时间字符串，不对可变小数位 RFC3339Nano 做字符串先后比较。

排序由不可变 seq 保证，不依赖可能倒退/同秒的时钟；单事件 lastSeen 不允许小于 firstSeen/已存 lastSeen。90 天政策仍依赖系统时钟可信：系统大幅前跳可能提前到期，回拨可能延后物理清理；硬数量界始终保留。不得宣称单凭 wall clock 能跨重启保证真实经过时长。

## 7. 安全 DTO、动作与分页合同

内部结构/SQL 行与公共 DTO 分开，禁止直接序列化数据库记录。

- 公开白名单：id、注册 type/family/severity、安全中文 summary、公开 sourceKind/sourceId、firstSeenAt/lastSeenAt/resolvedAt、occurrenceCount/capped、attentionVersion、isRead/isHandled、允许的 action 或 null。
- summary 只从本地代码目录按受限 code 生成固定模板；不插入标题、文件名、URL、query、异常、请求/响应正文、token/hash、privateRef、receiptId 或绝对路径。生产者即使称输入“已脱敏”，也没有任意字符串入口。
- 64 位 ID/版本/累计计数在 DTO/游标中用规范十进制字符串；limit、当前保留行总数/未读数等有明确小上限的数值可用 JSON number。空集合为 `[]`，缺失动作为 null。
- action 为固定 `kind + targetId`，例如打开已有 collection task；不返回调用方提供的任意 href。前端用静态路由映射；点击仍走原 API 鉴权与业务许可。标已读/已处理绝不触发重试、删除或提交。
- 验证目标是否仍存在时，先收集有限记录并关闭 Rows，再批量读取存在性，避免单连接嵌套借用。来源删除/不可用时 action=null，显示历史状态；不能凭事件恢复来源权限。

建议内部分页 query：limit 默认 30、范围 1..100；cursor 是有版本的、长度受限的规范编码，包含固定过滤条件、首屏 asOfSeq 和 beforeSeq。首屏取得当前最大 seq；后续只读 `seq <= asOfSeq AND seq < beforeSeq ORDER BY seq DESC LIMIT limit+1`。不使用 offset、不按 lastSeen 排序。游标不是授权凭证，仍严格校验规范整数、上下界和过滤绑定，不接收任意 SQL 排序/字段。

查询还须按本次请求的可信应用时间过滤已到期行；asOfSeq 仅固定新增行上界，不冻结年龄时钟。游标过久后可能自然得到空页，不能借旧游标继续访问已经超过保留窗口的历史。

只处理前 limit 行，第 limit+1 行只做 lookahead；nextCursor 使用最后消费的原始行 seq。若投影/验证跳过某些记录，不无限补页，允许 items 为空而 nextCursor 非空；S04.2 UI 必须允许手动继续查看。删行不要求 cursor 指向的行仍存在。

asOfSeq 防止后来新增挤动翻页，但不是跨请求数据库快照：已读/处理筛选、恢复、保留删除仍会影响后续页，可能少项；不许宣传绝对不漏的全局快照。过滤条件变化必须重新首屏。返回当前有界 unreadCount、retainedCount、retentionDays/maxItems、累计截断/未读截断计数及饱和标志，让用户知道历史可能已被清理。

S04.2 正式开放 HTTP 时还必须：已登录鉴权、原同源写校验、有界 body、精确 camelCase、拒绝未知/重复 JSON 和 query 键、空 query 值、尾随对象、超长/非法 cursor。批量确认上限 100，按请求看见的版本确认；空批/重复 ID/未知模式须有确定响应，不做隐式“全部当前及未来已读”。本研究不提前登记路由或承诺最终响应码。

## 10. 尚未解决/后续门禁

- 研究方案不是正式 PRD/接口冻结。实现者需把实际方法名、单一首接来源和新 schema 号写入 S04 `info.md`，再开始业务实施。
- 两表加来源水位的核心设计不保证每一个未接入模块都已具有可靠事实版本。尤其 jobs、下载连接、RSS 和可覆盖外部结果需按上表补契约，不能把“留了接口”写成“已接入”。
- 事件保留与原来源生命周期不同；S10 归档若搬移/删除来源，必须一起保留其去重水位或明确终结该来源身份，不能先删水位再把历史事实重新当新来源。
- 跨资源补记只可消费可靠持久事实；若现有结果会覆盖中间状态，不能无证据承诺完整 episode 历史。需要补足结果版本/重放能力，再做该来源联调。
- 事件统计允许保留截断，不是安全审计保证。真实时钟跳变、磁盘/数据库彻底不可写及数据库恢复会影响可保留历史，错误说明必须诚实。
- 未来 outbox 不得靠事件外键级联取消活跃投递，也不得为投递无限保留事件；应自持有界安全快照，此处未建表也未实现。
