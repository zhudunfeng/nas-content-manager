# NAS 内容管理系统首版实现

## Goal

根据用户“请按计划实现代码”的授权，交付视频、图片、漫画与小说统一管理的可运行首版，采用 Vue 3 + TypeScript、Go、SQLite 和单容器部署。保留以下方案研究作为设计背景，涉及“本轮不实施”“待批准”的历史表述由本节和首版边界取代。

## Approved implementation scope

- 首次管理员设置、登录会话、受控目录选择、四类媒体库、持久化扫描任务及重试/取消/重启恢复。
- 搜索、标签、收藏、继续播放/阅读与跨设备进度；响应式明暗主题界面。
- 视频直放（鉴权 Range/HEAD、有界内存、64 位偏移）、图片缩略图/大图、图片目录/CBZ 漫画、UTF-8/GB18030 TXT 和无 DRM EPUB。
- 单应用镜像、单服务 Compose、FFmpeg、数据库一致性备份及离线恢复文档。原媒体只读纳管。
- 首版不包含转封装、HLS/硬件转码、CBR/PDF、AI/爬虫；不支持的视频编码必须明确提示。
- 使用原生构建、接口集成验证及浏览器检查。Docker/真实 NAS 和超大真实影片的未验证事项如实记录，不将稀疏文件测试视作播放性能测量。
- 执行 Trellis implement → check → update-spec → finish；临时单元测试文件执行后清理，保留可复用集成验证脚本。

## Assumptions (temporary)

- 单台 NAS，个人或家庭少量用户，浏览器与移动端访问。
- 以纳管已有目录为先，原文件保持在 NAS 文件系统。
- Docker Compose 部署；实际 NAS 系统、CPU 架构、内存和核显能力待确认。
- 小说优先支持 TXT 与无 DRM 的 EPUB；其他格式后续评估。
- 漫画优先支持图片目录和 CBZ，采用系列/章节/页面结构；CBR、PDF 后续评估。

## Open Questions

- NAS 型号、CPU 架构、内存和硬件转码能力。
- 已按用户授权实施自建统一界面；后续第三方服务整合不属于本次范围。
- 内容规模、外网访问和多用户隔离需求。
- 超大视频的典型/最大体积、时长、峰值码率与编码，以及本地/远程观看场景；先按可扩展架构设计，不以未确认的大小作为产品上限。

## Requirements (evolving)

- 比较整合成熟工具、自建统一内容管理和混合方案，给出明确推荐与取舍。
- 四类内容使用共同的媒体库、标签、收藏、权限和进度模型，同时保留专属元数据与处理流程；漫画是独立入口。
- 说明文件扫描、异步衍生处理、搜索、播放/阅读与备份策略。
- 确定首版范围、暂缓功能、验收标准与分阶段顺序。
- 用户已批准本计划实施；具体硬件和性能不作未经验证的承诺。
- 默认使用一个应用镜像和单服务 Docker Compose，前端静态资源、后端和后台任务统一发布；数据库内置，不要求单独安装数据库、缓存或搜索引擎。
- 首次使用向导覆盖创建管理员、添加媒体目录、验证访问权限和启动扫描；普通用户不需要编辑内部配置。
- 响应式统一界面，视频、图片、漫画、小说拥有独立入口，共用搜索、标签、收藏和最近访问。
- 为升级、备份、恢复提供清晰入口与流程，明确原文件、业务数据和可重建缓存的差异。
- 界面以内容展示为中心：视频海报墙、图片时间线、漫画系列书架、小说书架；首页优先继续观看/阅读和最近添加。
- 提供明暗主题、统一图标与间距；字体与图标本地提供，基础使用不依赖公网字体或 CDN。
- 手机、平板和电脑均有明确布局；阅读/播放时弱化导航，退出后恢复原位置。
- 漫画提供单页、双页、连续滚动及左右阅读方向，按章节和页码保存进度；具体首版模式优先级在确认后确定。
- 超大视频纳入首版：鉴权后的 HTTP Range/HEAD、有界内存流式传输、64 位文件大小与偏移、断点续播和可取消的流请求。
- 优先直接播放，按需转封装/转码；不因文件体积大就默认全片转码、复制原片或启动 HLS。
- 扫描首轮不计算整片哈希，不以完整转码或全片缩略图生成为入库前置条件；探测、封面与索引增强后台限流执行。
- 分片/预取/转码缓存有容量、并发、低剩余空间与超时策略，避免超大视频消耗全部内存、磁盘或 CPU。
- 文件大小、视频码率、存储/网络吞吐、容器索引与解码能力分别诊断；界面显示准备、缓冲、转码、错误和恢复动作。
- 起播、拖动、连续播放、取消和故障恢复纳入真实大文件样本验收，性能目标待硬件/网络/格式确认后制定。

## Technical Approach（实施方案）

- 前端 Vue 3 + TypeScript + Vite；后端 Go 标准 net/http、modernc 纯 Go SQLite，已实现而非待选型。
- SQLite 放在 NAS 本机持久目录；版本化迁移与数据库访问层保留后续迁移空间。
- Web 静态资源与 Go 程序一起放入镜像（本机从 NAS_WEB_DIR 读取），持久任务队列与受管理的后台执行器同容器发布。任务限并发、可重试、支持取消和重启恢复。
- 使用 FFmpeg/ffprobe 等成熟工具处理视频；浏览器直播放优先，复杂编码和硬件转码单独验证。
- 超大视频采用文件句柄与支持随机定位的流式响应，走标准 HTTP 范围语义；按需处理与缓存使用版本化键和容量上限，详细设计见 [large-video.md](large-video.md)。
- 图片首版聚焦常见格式、缩略图和预览；漫画聚焦图片目录与 CBZ；小说聚焦 TXT 与无 DRM EPUB。
- 内容作品与文件位置分开，四类内容共享账号、标签、收藏与进度，专属元数据和处理器独立。图片与漫画可以复用底层图像处理，保留各自的信息结构和界面。
- 源文件默认只读纳管，增量扫描配合定期对账；源文件、业务数据和缓存分别制定保护策略。
- 详细组件边界、数据模型、部署与分期见 [info.md](info.md)。
- 视觉与交互建议见 [visual-design.md](visual-design.md)，当前仍为可调整的设计草案。

## Decision（ADR-lite）

**Context**：用户要求视频、图片、漫画、小说统一管理，同时强调易使用、易部署、界面美观；仓库无现有技术栈约束。

**Decision**：用户批准按计划自建轻量模块化单体，单应用镜像、单服务 Compose、内置数据库和统一界面，复用解析与媒体处理组件。

**Consequences**：用户部署与日常操作更集中；开发方需要实现统一产品的内容管理和消费闭环。首版支持格式应明确，暂缓 AI、分布式服务与复杂转码。若后续规模和写入并发需要，再引入外部数据库、队列或搜索服务。

## Implementation Plan

1. 统一基础：单容器发布、首次使用向导、媒体库、扫描任务、标签与收藏。
2. 四类消费闭环：视频直放与进度（包含超大文件流式传输、拖动与资源边界）、图片预览、漫画阅读、TXT/EPUB 阅读与进度、基础搜索；首个可用版本同时具备基础备份恢复。
3. 硬件与维护增强：按实际需求加入转封装/转码、硬件加速、权限细化和升级恢复验证。

## Definition of Done

- 交付可编译、可运行的首版代码，四类内容具备真实接口与播放/阅读闭环。
- 明确硬件依赖与待确认事项，不承诺未经测量的性能或工期。
- 完成接口联调、响应式浏览器检查与 Trellis 质量检查，沉淀实际代码规范和验证记录。

## Out of Scope (explicit)

- 首版不包含转封装、HLS 或硬件转码；编码兼容性由浏览器决定，并提供明确错误提示。
- 首版不默认包含爬虫、内容下载、AI 识别、原生移动端和分布式服务。
