# 外部资源组件平台部署与安装

## Goal

允许用户从当前平台触发 MoviePilot、AutoBangumi、Sonarr/Radarr 等资源组件的部署或安装，并在组件就绪后连接现有深度API管理。延续简单易用原则，避免把用户引导到割裂的手动部署流程。

## 已知事实与授权

- 用户明确要求优化当前平台，使其能够触发对应组件的部署或安装；属于在既有外部API集成之上的新增范围。
- 用户选择 **Docker 部署，支持 Linux NAS 与 Windows Docker 完整模式**；原生安装器不在本轮范围内，继续实现无需再次询问。
- 当前已有qBittorrent/Jackett私有helper、持久任务、Docker固定模板及Windows桌面Compose控制机制，不能从公开Web直接暴露Docker或任意命令。
- 支持MoviePilot、AutoBangumi、Sonarr、Radarr四个固定产品；不能变成任意镜像/命令/插件市场。
- 本轮实现产品能力并在隔离环境验收，不在开发机真实安装影视套件，不连接用户真实服务或改动实际媒体。
- 遵循AGENTS中文注释/日志、显式类型、CodeGraph检索、project_env包装器和新增临时单测完成后清除要求。

## Requirements

- 资源收集可选择连接已有服务或部署组件；常用流程简洁、中文状态清晰，高级参数渐进展开。
- 检测宿主/执行端是否具备安装能力，明确缺少的前提，不把不可用显示为可执行或假成功。
- 安装动作固定组件、固定受核验版本/镜像/目录/网络；持久UUID、确认、进度、失败恢复及重启对账。
- 组件实际API就绪才显示可连接；外部账号/站点/下载器初始配置与容器运行区分。
- 保留连接既有实例、现有API管理、独立完成目录导入及qB唯一任务所有权。
- 不接管同名外来容器，不自动删除镜像/数据，不把凭据写入浏览器日志/主库备份。

## Acceptance Criteria

- [x] 四类组件有可触发且受控的部署或安装路径；平台不具备能力时给出真实可操作说明。
- [x] 固定模板、权限/挂载/端口与归属验证，幂等和恢复协议有隔离验证。
- [x] 来源界面从检测到部署/就绪/连接有清晰路径，移动端和桌面均易用。
- [x] 现有外部API和引擎/媒体功能回归通过，Go/前端质量检查及适用跨平台构建通过。
- [x] 官方版本/部署依据、契约、使用说明与验收边界落盘；临时测试按要求清理。

## Technical Approach（已收敛）

- 复用现有私有 helper、持久任务库、唯一部署执行器、镜像层进度与 create/start 对账；新组件接口与原 qB/Jackett 接口分开验证，固定组件一次部署一个。
- 运维参数 `ENGINE_COLLECTION_ENABLED` 默认 false；仓库 Linux 托管 Compose 和 Windows 完整模式启用。原六角色不变，启用时额外固定 `collection-media` 角色，主应用只读挂载并仅授权其 `library` 子树。
- 四组件各自配置/缓存/数据库使用固定命名的本地 Docker 私密卷，创建前在私有 state 目录记录安装授权 nonce；重试核对卷标签和 nonce，不读取或预设组件密码、不接管未知同名卷。
- 四组件共同挂载 `/downloads`（现有受管下载根）及 `/data`（独立资源根）；推荐复制整理到 `/data/library/<组件>`，独立完成目录导入只读此子树。不自动配置 qB 账号、修改原 qB 模板或接管其任务；跨卷不宣称硬链接。
- 钉住四个官方版本和多架构摘要；默认宿主回环配置端口固定为 MoviePilot 19130、AutoBangumi 19132、Sonarr 19133、Radarr 19134。NAS 远程配置明确说明回环入口与 SSH 隧道，不误把浏览器本机地址当 NAS。
- 状态区分容器缺失/冲突/停止/启动中/HTTP可访问/应用连接；安装成功仅表示固定容器实际运行并响应匿名探针，随后显示“待首次配置”。MoviePilot3.2.8 首个管理员需通过 UI 创建，AutoBangumi 首次必须修改默认密码，Sonarr/Radarr 首次设置鉴权并获取 API key。
- 来源弹窗内提供“连接已有组件 / 在此部署”切换，嵌入进度与恢复，不叠加原生弹窗。部署后预填已验证组件的内部服务地址，用户输入自己的 API 凭据，再走原保存检测流程。MoviePilot 六项已实现工作流继续由能力检测启用。
- 停止完整实例必须包括四个新组件，仍不删除容器/镜像/卷；适当增加六组件顺序停止预算。

## UX 与验收边界

- 打开来源或读取状态不会拉镜像/建卷/启动。首次部署需主动勾选“创建固定组件及私密卷并允许访问下载和独立资源目录”的未选中确认。
- 同一个意图使用持久 requestId；网络丢失可重试读回原任务，刷新可恢复活动/最近组件任务。组件变更清空确认与旧任务视图，不让旧响应覆盖新选择。
- 停止/失败可显式启动或重试；其他目标忙、归属冲突、端口占用、helper不可用均给真实中文反馈。
- 不在开发机拉取或部署四个真实产品；隔离 Docker/API fixture 验证固定模板和完整流程，最终记录真实 NAS/Desktop 验收边界。

## Out of Scope

原生Windows/Linux安装器、任意镜像/命令执行、公开Docker socket、安装任意插件、自动配置真实站点/账号、删除数据/卸载清库、真实开发机部署、原生播放器/媒体服务器安装。
