# 补充归档知识沉淀并固定归档总结规则

## 目标

补齐 2026-11-27 批量归档 50 个 Trellis 任务时遗漏的项目知识总结，并将“先提炼项目可复用知识，再归档”固定为后续工作规则。

## 已知事实

- 用户要求 Trellis 归档时总结对当前项目有用的要点。
- 上轮已将 50 个活动任务归档至 `archive/2026-11/`，该目录还包含先前已归档的密码可见性任务。
- 原生 `task.py archive` 会将状态设为 `completed`，不能据此推断实现或目标环境验收已完成。
- 当前已有后端和前端可执行契约，应链接已有规范，避免复制并制造多个事实来源。

## 范围与要求

1. 从本次归档任务的 PRD、研究、验收记录及现有规范中提取可复用决策、踩坑、运行边界和下一步工作。
2. 总结应有来源路径，区分当前事实、历史验证、未验收事项和规划，不将所有归档任务宣称为已交付。
3. 形成可检索的月度归档总结，覆盖本次全部 50 个任务，并说明之前已归档任务的范围。
4. 将总结要求写入 AGENTS.md 的用户维护区域、Trellis 工作流、项目 finish-work 技能和指南索引。
5. 验证文档链接、任务覆盖、规则一致性与变更范围，保留上轮归档结果。
6. 本任务完成后先写任务总结，再归档本任务，保持活动任务列表为空；不自动提交 Git。

## 验收标准

- [x] 月度总结覆盖本次 50 个任务，并包含可定位的证据和待办。
- [x] 项目约束、Windows 分发/配置、资源收集/插件、NAS 规划的要点均有沉淀。
- [x] AGENTS.md、workflow.md、finish-work 技能要求归档前总结且区分归档与验收状态。
- [x] 指南索引可发现归档总结和归档检查清单。
- [x] 新增文档本地链接有效，原有归档资料保留；没有修改业务代码。
- [x] 本任务总结完成并归档，当前任务指针清除。

## 实施方式

- 按 Trellis brainstorm 创建任务；需求已明确，直接按用户要求实施。
- 使用 trellis-research 分别梳理 Windows/运行环境、收集/插件、NAS 规划与验收证据，各自写入本任务 research/。
- 主会话合并总结并应用 trellis-update-spec；依照 trellis-check 执行文档适用检查。

## 不包含

- 不修改产品功能、数据库或归档脚本行为。
- 不补做所有历史任务的完整测试，不把规划项自动转为已实现。
- 不创建新的业务开发任务，不覆盖已有归档内容或自动 Git 提交。
