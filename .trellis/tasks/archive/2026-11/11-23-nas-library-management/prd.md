# S08 筛选、批量管理与失联文件重关联

## Goal

扩展已有列表而非重建搜索系统，让用户按消费状态/标签找内容、执行小批量管理，并显式重新定位失联文件。状态：planning；相对工作量：大，可分段交付。

## 依赖与入口

- S08.1–2只需S01；S08.3在S05关联结构稳定后实施；S08.4作品/年份字段依赖S05/S06。
- 现有入口：`internal/app/items.go`、`models.go`、`store.go`、`jobs.go`、`media.go`、`download_gate.go`、`collection_import.go`；`web/src/App.vue`、`api.ts`、`types.ts`、`components/MediaCard.vue`。
- 拟新增批量/重关联计划模块，不将普通媒体操作塞进collection私有任务表。
- [总路线](../11-23-nas-evolution-plan/roadmap.md)、[拟议契约](../11-23-nas-evolution-plan/info.md)、[媒体研究](../11-23-nas-evolution-plan/research/media-implementation.md)。

## 范围与拟议契约

- 扩展现有GET列表：未看/进行中/已完成、missing、多标签精确AND/OR、有限数值范围；分页/白名单排序与未知值语义明确。
- 明确人工消费状态覆盖，不能通过伪造position/时长来标已看；原真实进度保留。
- 拟议batch首轮最多200个显式item ID，固定标签/收藏/消费状态动作，requestId和结果有界持久；短事务**全有或全无**，冲突列出需刷新的ID。
- 首轮重关联仅限旧文件已失联、目标未被其他item索引、配置内已授权同类型文件。preview/apply绑定revision、来源/目标版本及有效期；保留原item_id，不进行源文件操作。
- 保存筛选只保存校验后的筛选定义及版本，不保存任意SQL；作品字段等实际可用后才开放。

## 小 PR 顺序

1. **S08.1 查询与状态**：DTO/SQL/索引、稳定分页、显式消费状态与保存筛选；先用现有查询技术，在真实大库基准后决定是否需新索引方案。
2. **S08.2 小批量UI/API**：当前勾选数、动作预览、200上限、requestId重试、事务与冲突反馈；只修改应用数据。
3. **S08.3 失联文件重关联**：定位候选、只读安全核验、计划提交、活动任务冲突、保留身份/状态并使技术缓存失效；已索引目标拒绝并给说明。
4. **S08.4 依赖增强**：作品/年份等筛选接入S05/S06实际字段；再次验证组合查询与无元数据条目行为。

## Acceptance Criteria

- [ ] 状态定义、人工覆盖/恢复自动判定、标签AND/OR、空值、排序tie-breaker及跨页稳定性有断言。
- [ ] batch 0/1/200/201、重复ID、无效/过期条目、请求冲突、断网重试和全有或全无行为验证。
- [ ] UI不把当前页选择伪装为全过滤结果选择；切换筛选后选中集行为明确。
- [ ] 重关联拒绝可读旧文件、已索引目标、越界软链/未发布文件/类型不符、活动扫描/导入及预览后目标变化。
- [ ] 成功后保留item ID、收藏/标签/真实进度与作品关系，清理旧技术引用但保留人工锁定值；提示版本变化需校对进度。
- [ ] 拒绝路径下两个条目及所有状态保持；不自动合并、不自动改发布清单。
- [ ] 代表性大库查询记录数据量和延迟，不无依据承诺性能；隔离HTTP/迁移与五类媒体回归通过。
- [ ] 作品/年份筛选只在依赖就绪后开放，未知字段有清楚说明。

## 失败与回退

可关新筛选/批量入口，原列表保持。batch冲突整体不写，刷新后重试；重关联预览失败零写入，提交失败保持原身份，禁止文件侧补偿删除。已索引目标需未来专门合并方案，首轮不提供风险合并按钮。

## Out of Scope

批量删源、全过滤结果十万项隐式选择、自动hash合并、完整重复项状态合并、新独立全文检索服务、移动/重命名源文件。

## Definition of Done

执行父路线统一PR门禁与中文注释/日志、显式类型；扩展可复用集成脚本，新临时单测执行后删除；重关联结构风险需隔离复现并验证，不把旧评估推断当现成故障结果。
