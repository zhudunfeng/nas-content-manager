# S03.2.2 平台根与发布调试复盘

2026-11-23。本轮由主线整理既有实施交接和独立检查的调试事实；独立检查已停写，主线已完整读回最终报告及原始事件/源码/产物证据。本文不增加产品通过数，也不代替最终报告；主线未与 checker 并发改产品。

## 根因与此前假设

| 分类 | 失败假设及结果 | 已采用的修正和预防 |
| --- | --- | --- |
| Windows 句柄语义 | 以普通 Go 属性读取核对零共享锁，会与本进程持有的排他锁冲突；放宽共享会削弱互斥。 | 固定锁继续零共享；使用零数据访问句柄查询身份。核对锁目录项和原句柄，不 unlink 或重建锁。 |
| Windows DACL 表示 | 把 self/SYSTEM 权限假定为恰好两条 ACE，忽略 OICI/GA 的系统规范化及 self=SYSTEM。 | 按唯一 SID 核对有效/继承权限和标志，接受等价规范化；不扩大主体、权限或 DACL 保护范围。SYSTEM 分支覆盖与真实 SYSTEM 运行分开记账。 |
| Windows 路径解析 | 把 junction 当 Go symlink，或认为末端 EvalSymlinks 成功就已核实中间 junction；ModeIrregular 和中间路径语义使此前方案失败。 | 让内核解析配置入口，以句柄物理身份核对；保留原入口和父映射，换根再恢复仍持续阻断。不能只握旧物理根便继续写。 |
| ACL 副作用 | 在已有合法 marker 根上重设继承 DACL，看似只修根，实际可能传播到未知后代。 | 已有根只核验，拒绝也不修权限；仅初次证明空根后设置私有权限。真实未知深树的安全描述符和内容均要前后核对。 |
| Windows 别名规范化 | 只拒绝整段尾随空格及裸保留名，遗漏扩展名前主干的 ASCII 空格，CON .db、COM¹  .db 等被接受。 | 设备名检测在首个扩展分隔前去除主干尾随 ASCII 空格，再匹配保留名和上标数字别名；保留独立 red 事件后验证修复。不能以只测常见 CON.txt 代表完整别名边界。 |
| 资源错误传播 | Linux 打开 anchor 后首次 Stat 失败直接返回，丢弃 Close 的错误。 | 合并主错误与 Close 错误，逐资源所有权收尾；此修正仅静态复核和交编，不据此声称 Linux 动态故障通过。 |
| 夹具前提 | 权限、owner/状态或预算夹具自身不满足目标分支前提；深树失败夹具在移入前后修改继承的顺序也影响可读性。 | 保留原失败和命令；先证明夹具状态可达且权限可检查，再运行独立反例。夹具修正不算产品修复，重复轮次不累加。 |

这些问题属于实际平台语义、别名规范化和副作用边界，不能通过增加普通 rename/chmod/EvalSymlinks 重试解决。此前局部修正只覆盖了 API 表面或常见表示，没有同时观察原路径映射、实际句柄及未知后代。

## 后续执行约束

- S03.2.3 直接复用已验收的根、严格格式和平台发布原语；不要再引入另一套路径解析、ACL 修复、目录移动或快照服务。
- 成功路径必须有真实同 App/source 的产物校验；发布未知、清理失败及 Close 失败分别保留原 ID 与所有权事实，不从单一 error 推断没有 final。
- Windows 下，未知 final 的恢复确认仍须按下一片冻结契约执行，不能因为内容 hash 正确就视为 OS 发布协议已确认；正常 retained 根保持只读核验。
- 固定元数据长度是上限，不是必须填充到上限；摘要取原始 bytes，目录用 n+1 有界读取，不能重新编码或全目录读取后截断。
- 新临时测试执行后按确切路径和摘要清源；源码文本证据留在 .runtime。真实 Windows、Linux 交编、真实 Linux/NAS、进程中断、系统崩溃和物理断电分开报告。
