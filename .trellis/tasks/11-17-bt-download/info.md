## 2. 架构与职责

```text
浏览器：下载中心／添加弹窗
          │ 已有同源管理员会话
          ▼
Go API ── SQLite：任务、命令意图、文件清单、发布凭据
  │              │
  │ WebAPI       └─ 已发布 → 原有扫描队列 → items → 原生播放器／阅读器
  ▼
qBittorrent：BT 网络、分片校验、磁盘写入、恢复与做种
  └─ 专用下载卷：staging → complete
```

- 浏览器没有 qB URL／密码／SID，也不直接访问 qB 的 WebUI。
- 适配器提供能力探测、添加、查询、文件清单／优先级、开始／停止、任务级限速、移动、保留文件移除。首期只实现 qB 适配器，不做插件市场。
- 协调器由应用 ctx／WaitGroup 管理，独立于现有扫描 worker；qB 不通只降低下载模块可用性。
- 不直接读写 qB 的恢复数据库或内部文件；运行态通过公开 WebAPI，持久卷由其自身管理。

## 3. 路径、权限与发布门禁

### 3.1 默认布局

```text
宿主机现有媒体     -> nas:/media                 ro
宿主机专用下载根   -> qB:/downloads              rw
                   -> nas:/downloads             ro
    staging/<本地任务 UUID>/...                   未发布
    complete/video/<本地任务 UUID>/...            ready 后可索引
    complete/image/<本地任务 UUID>/...
    complete/comic/<本地任务 UUID>/...
    complete/novel/<本地任务 UUID>/...
    complete/music/<本地任务 UUID>/...
qB 配置恢复卷      -> qB:/config                   rw
应用数据卷         -> nas:/data                    rw
```

- `NAS_MEDIA_ROOTS` 在下载扩展中只额外授权 `/downloads/complete`，绝不把 staging 纳入普通可浏览根。
- UUID 防止同名种子覆盖；媒体标题仍使用原文件／目录名。种子提供的名字不能决定绝对保存路径。
- 用户在添加时授权创建或使用同类型下载库。首次发布确认目录存在后，再按标准创建逻辑登记 `/downloads/complete/<type>`；删除库后不静默重建，任务显示目标库缺失并要求重新选择。
- 外部引擎可用配置中的“引擎根→本地根”映射，必须按路径组件匹配，验证本地真实文件后才能发布；不接受前端传入的任意映射。
- 两个目录建议位于同一真实文件系统；路径文字相近不能证明同盘。不能确认时提示可能发生复制，并禁止把移动 API 成功当作文件就绪。

### 3.2 发布步骤

1. 获取并固定所选文件清单及版本，校验路径、类型、数量、尺寸。
2. 对账引擎：元数据完整，所有所选文件完成，无下载／校验／移动过程；完成时长／进度单字段仅用于展示。
3. 持久化移动意图，调用 `setLocation`；其成功响应只表示接受请求。
4. 轮询确认最终保存位置，等待 moving／checking 结束，核对所选路径存在、是常规文件、尺寸与清单匹配、无越界链接；不再对全片做额外内容哈希。
5. 以短事务发布该版本清单为 ready，触发标准幂等扫描。无匹配可阅读文件则保留下载，标为无可导入内容。
6. 扫描结束后核对 items／目录漫画结果，再标记 imported；探测封面失败独立展示，不把下载改为失败。

`enqueueScan` 可能复用已经遍历过新目录的运行中扫描，不能将“某次扫描完成”直接视作本次清单已入库。记录清单版本与扫描代次，结束后核对实际覆盖；未覆盖则合并安排一次后续补扫，直到本次 ready 清单被实际索引。无支持文件由清单类型判断，不把补扫遗漏误报成无支持内容。

必须先登记受管任务与隔离目录，再向引擎添加任务。即使程序在第 3–5 步退出，重启也从本地意图与引擎现状继续，而非重复移动或再次添加。

### 3.3 门禁实现要求

- complete 下的受管命名空间采用默认拒绝：无 ready 清单、移动中或已失效目录统一跳过。上传／元数据确认前没有发布权限。
- 同一门禁用于手动／周期扫描、嵌套库创建／目录浏览、目录漫画页枚举、增强任务、媒体打开；不能只过滤 `.part` 或 `.!qB` 后缀。
- 所选清单覆盖目录漫画的图片计数、尺寸、页列表和封面来源；未选文件即使有预分配实体也不可读入。
- 引擎离线本身不撤销已确认发布的本地内容；发现源变化、重新下载或清单改变时先冻结受影响目录并重新验证，不让陈旧完成标志授权半成品。
- 冻结／离线的目录不能让全库扫描把旧内容批量标记 missing；保留旧索引与个人状态，媒体访问返回明确的暂不可用原因。
- 任务“移除”保留发布记录与文件清单，可归档隐藏；不能 cascade 删除发布授权。原媒体库删除也不删除下载数据。
- 下载根不能通过另一个只读媒体挂载暴露同一 staging。部署检查结合真实路径／文件身份；检测到别名或无法证明隔离时拒绝开启，不仅比较容器路径字符串。

## 4. 建议数据模型：SQLite v2

下载功能需要持久化新状态，不能沿用音乐功能“无需迁移”的结论。保留所有 v1 表，新增以下概念；实际 SQL 由 P1 细化。

| 表 | 中文字段说明与约束 |
| --- | --- |
| `downloads` | 本地 UUID、所属引擎绑定、v1／v2 哈希别名、展示名、内容类型、目标库、staging／complete 相对路径、创建状态、期望动作、引擎原始／归一状态、入库状态、清单版本、发布时间、最后同步／错误、归档标志；已发布任务不物理删除 |
| `download_files` | 任务 UUID、清单版本、引擎文件索引、受控相对路径、64 位尺寸、是否选中、确认完成状态；联合键防止清单重复，发布时冻结选集 |
| `download_operations` | 请求幂等键、任务 UUID、命令类型、修订号、待发送／待确认／结果不确定／完成／失败状态、尝试次数、下次重试时间、脱敏错误；用于跨进程恢复命令意图 |

- v1／v2 哈希作为带算法的身份，不把“哈希固定 40 字符”写死；混合种子两个身份都应命中同一任务。引擎短标识不能当作完整 v2 身份。
- 对本地 requestId 唯一约束；每个有效引擎哈希只能属于一个未归档的受管任务。归档后重加先明确复用／重新校验已有数据，不盲目覆盖。
- 引擎端 tag 含栖库命名空间与本地 UUID；命令执行前联合验证本地记录、哈希、标签和保存路径，不通过任意 hash 操作非受管任务。
- 速度／连接数等高频数据保留于有界内存快照；状态转换及时落库，统计低频节流保存，不每两秒重写所有行。
- 新迁移在一个事务内更新 user_version；失败回滚。新程序仍拒绝更高未知版本，旧程序将拒绝 v2，回滚需配套恢复 v1 快照。

## 5. 状态机与对账

### 5.1 三条独立状态轴

| 轴 | 建议状态 | 含义 |
| --- | --- | --- |
| 连接 | disabled / connecting / ready / offline / auth_failed / incompatible | 引擎模块状态，影响整组任务的实时性，不覆盖任务本身历史状态 |
| 下载 | submitting / metadata / awaiting_selection / queued / downloading / paused / checking / moving / seeding / completed / error / missing | 映射引擎状态，保存原始值便于版本排错 |
| 入库 | pending / publishing / queued / scanning / imported / no_supported_files / failed / target_missing | 下载已完成也可能尚未入库；其失败可单独重试 |

UI 在引擎离线时附加“上次同步于…”，速度视为未知；不能展示陈旧速度为实时速度。上传活动不代表视频未完成；做种可以与 imported 并存。

### 5.2 幂等与恢复规则

- 先持久化本地任务／命令意图，再发网络请求；发出后超时标为不确定，通过 hash／tag 查询收敛，不能立刻重发 add。
- 元数据／文件选择／移动命令均携带本地修订号，只允许当前修订更新状态；操作串行化，过时响应不能覆盖暂停／移除等新意图。
- 应用重启不改变引擎已经运行的下载；先恢复协调器并对账，继续补做未完成发布／入库。引擎重启恢复依赖其持久化配置与 BT 恢复数据。
- 引擎里任务消失标为 missing，提示用户；不凭本地旧记录自动重下。外部修改路径／标签导致绑定不符时停止自动写操作。
- 未确认的添加源可在 `/data` 以 0600 有限暂存；确认后清理。原始磁力／种子可能含私有 Tracker 参数，不放日志、普通 API 或普通进度行。历史任务丢失需用户重新提供来源，不能承诺备份数据库就能重建所有引擎任务。
- 每次只进行有限量对账；建议活跃任务每 3 秒、空闲每 15 秒、故障退避到 60 秒。界面可每 2 秒读取后端缓存，隐藏页面停止轮询，不因打开多个页面放大引擎请求。
- 连接超时、响应体上限与重试次数均有边界；登录刷新合并，凭据失败不无限登录。所有网络等待在事务与现有任务锁之外执行。

## 6. API 草案

所有路由使用现有管理员会话、同源保护、camelCase、中文错误和数组非 null 规则。下载功能关闭时状态接口仍返回 disabled，其他下载写操作返回明确不可用原因；不更改基础 `/healthz` 成功语义。

| 方法与路由 | 输入／输出与约束 |
| --- | --- |
| `GET /api/downloads/status` | 开关、连接状态、实际引擎／WebAPI 版本、能力、最后同步、受管任务汇总与脱敏错误；不返回密码或 SID |
| `POST /api/downloads/connection-test` | 只测试后端已配置连接，不接受任意 URL；返回可理解的认证／版本／映射诊断 |
| `GET /api/downloads?state=&q=&page=1&pageSize=30` | 分页任务、下载／入库状态、数值单位、快照时间和 stale 标志；pageSize 最大 100 |
| `POST /api/downloads` | JSON 磁力或 multipart 单种子；含 requestId、contentType、目标下载库授权和任务级选项；返回 202 与本地任务 |
| `GET /api/downloads/{id}` | 详情与允许执行的动作；文件清单独立分页，避免大种子压垮响应 |
| `GET /api/downloads/{id}/files?page=&pageSize=` | 已验证的相对路径、文件索引、大小、选择与完成状态 |
| `PUT /api/downloads/{id}/selection` | 已显示清单版本、选中的文件索引；版本过期／已开始正式下载返回 409，拒绝空选集 |
| `POST /api/downloads/{id}/actions` | requestId、revision 与 start / pause / reconcile / remove；remove 仅保留文件，返回接受状态，由对账确认 |
| `PUT /api/downloads/{id}/limits` | 任务级下载／上传 KiB/s，0 表示不额外限制任务但仍受引擎全局限速约束，不接受负数；不改已有实例的全局设置 |
| `POST /api/downloads/{id}/retry-import` | 重试发布验证／入库，不重新添加种子，复用原有扫描去重 |
| `GET /api/downloads/{id}/items` | 对应已入库内容的分页列表，支持一个多文件下载对应多个 Item |

任务 DTO 中的 `sizeBytes`／`downloadedBytes` 使用字节，速度为 bytes/s，`etaSeconds` 可为 null；分享率是无单位比值。不要在同字段中混用 KiB/s 和 bytes/s。JS 检查安全整数，异常大值明确拒绝或使用已约定十进制字符串，不悄悄舍入。

实施限额：种子本体最大 8 MiB，multipart 总额 8 MiB+64 KiB；普通 JSON 仍为 64 KiB，仅文件选择 PUT 独立放宽至 256 KiB，以容纳最多 20000 个非连续引擎索引。超额统一返回 413，不全局取消限制。限制解析深度、字串与文件清单及引擎响应体；精确预算集中定义并有中文说明。拒绝无效 bencode、特殊文件和越界路径；计算 v1 身份时使用原始 info 字典字节，不能重编码后冒充原 hash。

错误约定：未登录 401、跨站 403、无效输入 400、版本／状态／重复冲突 409、超量上传 413、不支持内容 422、引擎关闭／离线 503、引擎超时 504。应用会话过期才触发前端退出；qB 凭据失效属于下载模块错误，不伪装成栖库会话 401。

## 7. 引擎适配与技术探针

实施 P1 先用锁定版本验证下列契约，结果写入研究／验收记录：

1. 登录 Cookie、Origin／Referer、Host 校验与 WebAPI／应用版本探测；实际 5.2.4 返回 HTTP 204／空正文及 `QBT_SID_<端口>`，适配器保存并回送实际受限名称，兼容旧 `SID`；不通过关闭认证／CSRF 保护解决连接问题。
2. 5.x 的 `stop`／`start`、`stopped` 参数与旧文档示例差异；不依赖自动猜版本或对失败请求无限尝试。
3. `.torrent` 添加为停止态；磁力获取元数据与 `stopCondition=MetadataReceived` 的实际状态，何时可安全设置选集和读取完整身份。
4. v1／v2／混合的 hash 表示、去重、tag 关联和添加超时后的查询；HTTP 200 不等于添加成功或内容已完成。
5. 所选文件完成、分享状态、checking、moving、错误与任务消失的映射；多文件边界分片和未选占位符的行为。
6. `setLocation` 异步移动、同盘／跨挂载差异、断电恢复后的最终路径，以及 `.parts` 等附属文件不被入库。
7. 官方镜像指定标签、UID／GID 与配置目录、首次临时密码设置固定密码的可执行流程；记录 amd64／arm64 镜像清单但不运行 Docker。

文档与锁定版本不一致时以公开接口实际行为／固定版本源码及探针为依据，更新适配器契约，不偷偷扩大兼容承诺。

## 8. 部署与配置

交付 `compose.downloads.yaml` 作为覆盖文件，基础 `compose.yaml` 无下载依赖。复用已有 qB 时不启动新容器；新增实例才启用 qB 服务。普通模式只暴露栖库端口，BT peer TCP／UDP 端口单独映射；WebUI 临时初始化入口限制本机或受控 LAN，设固定密码后撤销额外映射。不要将宿主 Docker socket 挂进应用。

| 建议参数 | 默认值 | 中文解释 |
| --- | --- | --- |
| `NAS_DOWNLOAD_ENABLED` | `false` | 是否启用下载模块，未启用时不连接下载器 |
| `NAS_DOWNLOAD_QB_URL` | 空 | 后端连接 qB WebAPI 的固定 HTTP(S) 基地址；启用时必填，禁止 URL 自带用户名密码 |
| `NAS_DOWNLOAD_QB_USERNAME` | 空 | qB WebUI 用户名；只用于后端登录，与栖库账户独立 |
| `NAS_DOWNLOAD_QB_PASSWORD_FILE` | 空 | 只读凭据文件路径，启用时必填；内容不写入数据库备份或日志 |
| `NAS_DOWNLOAD_ROOT` | `/downloads` | 栖库可读的专用下载根；其 staging 不属于媒体根，容器只读挂载 |
| `NAS_DOWNLOAD_ENGINE_ROOT` | `/downloads` | qB 看到的同一宿主下载根，用于受控路径映射 |
| `NAS_DOWNLOAD_MIN_FREE_GB` | `2` | 下载卷保留空间，单位 GiB，独立于封面缓存预算；不能保证其他进程不会占用空间 |
| `DOWNLOAD_PATH` | 必填 | Compose 宿主专用下载目录的绝对路径，qB 读写与栖库只读挂载必须指向同一目录 |
| `QBT_IMAGE` | `5.2.4-1` 固定摘要 | 官方多架构镜像，完整摘要及来源见 `.env.downloads.example` 和 `docs/downloads.md`；本次不执行 Docker |
| `QBT_UID`／`QBT_GID` | `1000`／`1000` | 下载进程宿主身份，映射到官方镜像实际支持的 UID／GID 参数；保证栖库身份可读取文件 |
| `QBT_PEER_PORT` | `6881` | BT peer 的宿主 TCP／UDP 端口，与 WebUI 管理端口不同 |

后端内部同步周期、响应体预算和解析限制先作为带中文注释的集中常量，避免把每个实现细节变成必填环境变量。界面高级选项提供任务级限速；已有引擎的全局队列、DHT／PEX／私有种子策略与其他任务不被自动改写。

官方镜像初始化若不能按文档安全完成，P1 必须显式解决并记录；不能把“自动生成配置密码”当作镜像已有功能，也不能把关闭鉴权列为易部署方案。

## 9. 资源、空间与备份

- 新建独立下载器可采用低并发起点（例如同时下载 2 个），但该值是建议调优，不能覆盖用户已有实例的队列策略；带宽默认值需按 NAS／网络实际设置。
- 启动下载前合并受管任务的预计剩余写入预算，避免多个开始请求同时通过同一剩余空间检查；预算不是跨进程磁盘配额，下载时继续检测并处理 ENOSPC。
- 预分配可能带来长时间磁盘操作，首期不默认强制全量预分配。断点校验可能读取整片，这属于 BT 正确性需求，不能对用户承诺始终瞬间恢复。
- 不修改现有原文件 Range、16 路媒体流槽位或扫描锁协议。下载与播放竞争磁盘时，通过下载任务限速／并发保护，不扩大 Go 缓冲区解决磁盘瓶颈。
- `/api/backup` 仍是应用 SQLite 一致性快照，含新增表；不包含媒体、qB 配置／恢复状态、独立密码文件或尚未确认的暂存种子。完整恢复须分别备份这些持久目录，明确顺序与权限。
- 回滚到旧应用时同时恢复对应 v1 数据快照；仅撤销下载开关不会将数据库自动降级。原下载数据和引擎恢复卷保留，避免恢复时生成第二份文件。
