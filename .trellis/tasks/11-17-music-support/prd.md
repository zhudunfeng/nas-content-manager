# 音乐内容管理与播放

## Goal

在栖库现有视频、图片、漫画、小说之上增加音乐，让用户以相同的建库、扫描、搜索与收藏流程管理 NAS 音频，并直接播放、跳转与恢复进度。

## Requirements

- `music` 成为第五种 ContentType，贯通建库、类型过滤、统计、后台扫描、详情、标签、收藏与继续播放。
- 扫描 MP3、M4A、AAC、FLAC、OGG、OPUS、WAV、AIF/AIFF；MIME 使用稳定的显式映射，大小写不敏感。
- 通过已有异步有界 ffprobe 机制提取音频时长；有内嵌封面时有界提取，没有封面时正常完成并使用音乐专属占位封面，不能在每次扫描反复生成失败任务。
- 不增加额外部署服务和运行配置；复用现有鉴权 `/file` 的 GET/HEAD/Range，不全量下载为 Blob。
- 原生 audio 控件提供播放、暂停、拖动与音量；秒数进度在暂停、跳转、关闭时保存并恢复。关闭释放 src 与网络连接；未恢复完成前不能覆盖既有进度。
- 沿用石墨/青绿色和浅色主题，加入音乐图标、正方形封面与音乐播放器。桌面直接入口；手机主导航最多五项，通过明确的“更多”或内容选择入口访问全部类型。
- 浏览器不支持的封装/编码显示中文错误与下载入口，不虚构转码能力。
- 检查旧数据库兼容；现有 v1 类型列无 CHECK 且已有 duration，无需新增字段或迁移。必须用旧四类型数据验证新增音乐后状态仍保留。
- 保留原四类型行为及大视频 64 位 Range 优化。所有新方法、字段与配置按 AGENTS.md 添加中文注释和显式类型，关键操作中文日志。

## Acceptance Criteria

- [x] 新建音乐库后异步扫描出支持音频，非音乐文件忽略；重复扫描稳定 ID，收藏/标签/进度保留。
- [x] 音乐 API 过滤、空统计、时长、鉴权 HEAD/Range/416、收藏标签与进度通过集成验证。
- [x] 内嵌封面正确提取，无封面音频任务正常结束；无工具/损坏音频可见且错误明确。
- [x] 浏览器真实音频可播放、seek、恢复进度，关闭释放 src；未加载即关闭不重置进度。
- [x] 两主题 375/768/1024/1440 无横向溢出，手机全部五类型可达且主导航不超过五项。
- [x] 旧 v1 数据及原四类型集成回归通过，数据库版本和用户状态完整。
- [x] gofmt/vet/test/build、前端 typecheck/build 和独立检查通过，README/API/spec/验证文档同步。

## Technical Approach

共享契约保持 Item 结构不变，`duration` 解释为音视频时长；Stats 新增 `music: number`。后端拥有 internal/app，前端拥有 web/src，主代理维护集成脚本、任务与文档。复用媒体鉴权、流式读取、任务预算和个人状态表，避免为一个内容类型引入数据库重建或独立播放器依赖。

## Design

采用现有组件与语义颜色；音乐卡片与封面为唱片/专辑式方形展示，播放器集中呈现封面、标题、格式时长、原生音频控制与下载。使用 SVG 音乐图标，不添加外部字体或图片。手机以不超过五项的底栏及可见内容选择菜单兼顾全部类型，菜单具备键盘和焦点支持。

## Definition of Done

记录真实运行证据、清理本任务临时单元测试、关闭隔离测试服务。Docker 部署由用户手动验证，本任务不运行 Docker，不自动提交 Git。

## Out of Scope

云端音乐源、歌词下载、专辑/艺人实体、歌单、全局后台迷你播放器、自动连续播放、音频转码；这些不阻塞第五类型的完整基础流程。
