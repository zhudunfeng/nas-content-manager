# NAS 内容管理系统逐步实施路线

日期：2026-11-23。规划基准：`main / 6f380be`。用户已授权逐步实施；S01/S02、S03.1/S03.2.1/S03.2.2本机验收完成。用户进一步要求快速形成可用版本，本轮优先生成当前Windows开发可用包，见[启动说明](../../../docs/usable-preview.md)；S03.2.3契约已冻结、未完成草稿隔离，后续继续。各步骤开始前对当前代码与迁移版本做增量复核，真实设备发布门禁单独保留待验。

## 1. 执行原则与推荐路线

继续面向个人/家庭局域网 NAS、单管理员和现有 Go/SQLite/Vue 架构。复用已经实现的五类媒体、RSS/自动规则、原生获取→发布→扫描核验、外部组件接口以及一致性数据库快照，不再建设一套平行系统。

推荐依次交付：**S01 基线 → M1 能管理且能恢复 → M2 内容可整理且可消费 → M3 无人值守且可维护**。同一时间默认推进一个实施任务，每项按 PR 切片交付；下表的顺序是默认排队顺序，不等同于所有任务都有串行技术依赖。

工作量为相对级别：小＝约 2 个可验收 PR；中＝约 3 个；大＝约 4 个或包含明显跨层迁移。它不换算日历日期；每个 PR 的完成条件是可运行、可验证、可停在当前状态。真实设备等待单独记录。

## 3. 三个里程碑及出口

### M1：能持续使用、能恢复（S02–S04）

- 用户能改密、撤销其他设备会话；忘记密码时有需停机与持有数据目录权限的离线恢复路径。
- 系统按计划生成可校验快照，失败可见；在隔离实例按清单恢复账号、收藏、标签、进度，并报告未包含的秘密/组件数据。
- 关闭网页后关键失败仍可在下次登录看到；配置通知时可选离站提醒，不泄露秘密。
- 发布门禁：目标部署上的数据锁、重启、备份空间不足、隔离恢复演练留有证据；没有设备时只标为“本机通过、目标待验”。

### M2：内容好找且能消费（S05–S08）

- 电影和剧集可以按作品/季集展示；未归组文件继续可用，老链接和个人状态保持。
- 已有 NFO/海报可用，人工修改有来源/锁定且不会被重扫覆盖；人工上传资产能恢复。
- 字幕可选，资源能回收；不能播放时能区分容器/视频/音频/浏览器支持问题，明确诊断置信度。
- 筛选和批量操作可预览；小批量按全有或全无提交，冲突明确指出需刷新的条目；重关联不自动合并收藏/标签/进度。
- 发布门禁：代表性目标浏览器和真实大媒体的起播、拖动、并发扫描与资源峰值测量；协议 fixture 不能替代这些。

### M3：无人值守与长期维护（S09–S12）

- 指定完成目录经过一次明确映射后可持续发现并导入；系统能追踪到真实扫描条目，不以下载完成代替入库完成。
- 暂存、缓存、组件卷和媒体容量口径明确；历史可归档，清理前验证活动任务、做种、索引引用和发布证明。
- 规则能解释“为何命中/未命中”；缺集依据明确，重复和未知外部写入转人工处理。
- 组件先完成实际状态/版本和单组件维护，再按实测兼容矩阵开放升级；不能验证可降级时不显示一键回滚。
- 发布门禁：真实组件完整流程、UID/ACL/挂载、重启/断连、恢复及保数据维护演练。

## 4. 第一项执行卡

本执行卡保留S01的重放步骤。2026-11-23已完成本机基线与档案模板：两次core各52项，下载36项/外部83项/发布边界83项，最终编排自检39项；真实设备待验。S02、S03.1/S03.2.1/S03.2.2也已本机验收。当前优先交付可用包，下一实施片为 **S03.2.3**；S03未整体完成，无需重做功能缺口调研。

1. 激活 `.trellis/tasks/11-23-nas-validation-baseline`，读取其 PRD、父计划契约及现有验证说明。
2. 确认当前 Git 基准与工作区，保留用户已有改动；用现有 CodeGraph 索引定位受影响入口，索引过期才更新。
3. 盘点 `scripts/verify*.py`，将命令、输入、断言、产物、当前运行结果分开登记；先跑核心最小基线，再按后续任务触发领域脚本。
4. 建立真实 NAS 档案模板，记录 OS/架构、Docker模式、UID/ACL、卷映射、CPU/内存、媒体样本和客户端；未知填写“待提供/待验”，不能编造。
5. 输出可重复的本机结果与目标设备待验表；随后激活 **S02**，进入账号生命周期实现。

统一命令入口（参数按子任务/脚本实际帮助确定）：

```powershell
python -B scripts/project_env.py -- python -B .trellis/scripts/task.py start .trellis/tasks/11-23-nas-validation-baseline
python -B scripts/project_env.py -- python -B scripts/verify.py --help
```

`verify.py`需要先启动隔离实例并传`--base-url/--root`；收集脚本还需worker产物。S01先核对参数并编排，不能把脚本名当作自动启动命令。本轮规划没有执行上述业务验证。首次实施遇到缺依赖先记录和解决，不能将“未运行”记为通过。

## 5. 每个 PR 的统一完成规则

1. 开始前核对当前实现与 `PRAGMA user_version`；数据/API/事件变更先在任务明确契约，不预占所有未来 schema 版本。
2. 保持单个 PR 的功能切片完整：迁移、Go类型/中文注释/日志、接口、TS类型、UI状态及相应验证一并完成；纯基础片可暂不暴露 UI。
3. 运行变更对应检查；涉及后端执行 gofmt/vet/build及有实际断言的测试，涉及前端执行类型/构建检查，跨层执行对应隔离集成脚本。命令均经项目环境入口。
4. 本轮新生成的临时单测按用户要求执行后移除；稳定回归断言保留在可复用集成脚本，不删除原有测试。
5. 记录真实执行环境、结果、剩余目标验收；更新实际已实现契约与文档，未实现内容继续留在任务。
6. 对失败升级、未知外部写入和清理操作给出可停止路径；验证备份前不做不可逆迁移/清理。提交由用户决定，本计划不自动提交/部署。

## 6. 后续分支与升优先级条件

| 分支 | 触发条件 | 推荐最小切片 | 与本路线关系 |
| --- | --- | --- | --- |
| 家庭多用户与库权限 | 开始让多个家庭成员分别使用，或准备公网访问 | 去除单管理员约束的迁移设计→角色/库授权→个人状态隔离与越权验证 | 此时升为 P1，先做授权再扩大访问；不只增加登录框 |
| 音乐连续播放 | 音乐成为主要使用场景 | 全局播放器→队列/上一首下一首→循环/随机→歌单/专辑 | 可在 M1 后分支，不阻塞作品模型 |
| 阅读深化 | 经常阅读长篇且需要定位/检索 | 书签→受限正文索引→高亮批注 | 书签先行，全文索引由真实规模决定 |
| 图片与相册 | 主要管理照片而非漫画/文件预览 | 跨页浏览→只读 EXIF→虚拟相册/时间线 | 不写回源图，位置隐私另列契约 |
| 转封装/音频转码 | S07 实测确认高频容器或音轨问题 | 有界任务→按需产物/Range→取消/回收→资源并发限额 | 独立条件任务；硬件视频转码更后，须设备验证 |
| 通用插件/飞牛 | 有明确宿主和插件需求 | 复用 [既有规划](../11-19-plugin-market-fnos-plan/prd.md)，先复核当前四组件与协议演进 | 不复制旧 v2/两引擎假设，不与 S12 混同 |
| 大屏/外部播放器、更多格式、发行升级 | 有实际设备/库存/分发需求 | 先做单一设备或格式的完整闭环 | 单列任务，不纳入本轮十二步 |
