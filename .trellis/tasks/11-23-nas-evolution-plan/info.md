# 实施前的拟议跨层契约

本文件是 2026-11-23 的设计输入，**所有新增表、字段、路由、命令名均为拟议**。现有行为仍以当前源码、`docs/api.md` 及 `.trellis/spec/` 为准；每个子任务实施时确认最终名字/错误码/迁移版本后再更新相应规范。本轮不改数据库或正式 spec。

## 1. 共用不变量

- 只读媒体路径和受限根目录继续生效；NFO/字幕/海报不能绕过 canonical root、符号链接、文件大小与路径隔离检查。
- 保留已有 `users`、`items.id`、`user_items`、`progress`、任务和发布凭证。作品是附加关系，不替换文件身份，不重建既有主键。
- SQLite 沿用单连接与增量事务迁移；长时间 I/O、探测、远端调用和文件复制不能持有事务。实施时基于实际 `user_version` 安排下一个迁移，拒绝新库降级。
- JSON继续 camelCase、数组为 `[]`、错误为中文说明；状态/冲突/未知结果需要机器可判别字段。所有管理变更保持鉴权、同源校验、限长和严格输入解析。
- 后端配置经现有配置入口校验，参数有中文解释；新增调度/导入默认关闭或需首次确认，不能在升级后突然开始写入或删除。
- 继续使用持久任务与统一取消/重启生命周期。不确定的外部写入只对账或交人工，不能因超时/重启直接重发。
- 新方法、实体字段、关键逻辑、配置参数按项目中文注释/中文关键日志与显式类型要求执行；秘密不得进入日志、事件、导出和命令行。

## 2. S02：管理员与会话

拟议接口域为 `/api/account/password`、`/api/account/sessions`：已登录改密要求校验原密码，新密码使用当前新建密码政策；旧弱密码/中文密码仍可作为原密码校验，不被新政策提前拦截。改密在同一事务更新 hash 并撤销全部旧会话，成功后重新登录；会话列表只提供安全客户端说明/创建时间/当前标志，不提供 cookie 或摘要。

会话记录可增量添加公开随机编号、创建时间和受限 user-agent 描述；旧行创建时间允许未知，不因字段缺失失效。账号/会话增量增加auth_revision，登录在bcrypt校验后建会话需CAS核对原修订/密码快照，阻止并发改密后旧密码线程补建有效会话。单会话撤销校验归属，revoke-others再认证后保留当前；“当前会话”不能按列表第一个猜测。撤销作用于提交后的新鉴权请求，已准入传输可能完成，敏感变更提交时再次核验。

拟议离线重置命令属于本地 CLI，先获取现有 canonical 数据目录 OS 独占锁，再只打开账号所需存储；服务仍持锁则拒绝，不调用会迁移/恢复任务/清缓存的完整服务初始化。仅操作已有且版本可支持的数据库。密码经无回显交互或显式password-stdin提供，不经 argv/环境变量/日志。明确目标 profile，不删除用户、不重跑 setup，事务更新密码/修订并撤销所有会话；Windows/Linux都需验证。浏览器不提供匿名重置接口。

## 3. S03：快照、备份集与恢复检查

区分两种能力：

1. 运行中 **应用数据库快照**：复用现有 `VACUUM INTO` 语义和独占临时目标，完成完整性/外键/版本检查后原子公布；失败不得取代最后成功备份。
2. 停机 **完整恢复材料集**：应用数据、来源秘密、helper身份、worker持久状态、组件配置卷/下载与媒体挂载映射。网页不能声称已复制自己不可访问的 Docker 卷；缺项明确记录 `externalRequired` 与采集步骤。

拟议备份清单包含：格式版本、生成时间、应用/数据库版本、备份类型、相对文件名/大小/摘要、资产类别、缺失必需材料、源挂载映射说明。秘密原文不进入清单；目录越界/符号链接/重复成员/错误摘要应拒绝。未加密的备份集必须有明确权限与离线保管说明，不能把压缩当加密。

人工上传原始海报/自定义素材是**不可重建用户资产**，需在独立持久资产区纳入备份；派生封面/探测缓存可重建，可只登记。S03先实现通用资产登记/清单、受控文件采集与恢复，以合成原件独立验收，不等待S06。S06.3再负责真实上传原件的端到端恢复演练，通过后才开放入口，不能把原始素材放进可清理缓存。

第一版只支持单条每日UTC固定时间，UI显示本地换算，暂不支持任意cron；持久化策略修订/下次计划/最后成功失败/执行记录。单实例错过多个周期最多补最近一次，时钟回拨/重启不重复既有schedule_key。轮转只触及已完成且属于本应用的备份，成功发布新备份后才评估保留策略，永远保留约定的最后有效恢复点，活跃下载文件跳过。

拟议离线检查器默认只读检查，输出 `ready / incomplete / incompatible / invalid` 及中文步骤；不原地覆盖生产目录。隔离恢复先复制到新目录，在受控阶段获取独占锁/校验版本，再经独立显式的离线恢复准备步骤撤销全部快照会话（受支持版本含auth_revision时一并推进），之后才启动验证/对外服务；恢复准备不能藏进只读检查器，不改密码、不启动任务或隐式迁移。外部任务未知状态保留人工对账，不能自动继续外部写操作。回退是停止新实例并恢复迁移前备份；不是让旧二进制直接打开新库。

## 4. S04：持久事件与通知

拟议事件记录含稳定类型、严重级别、去重键、来源任务/组件标识、受限中文摘要、发生/更新时间、未读/已读/已处理状态和可授权操作链接。事件去重与处理状态独立：同一故障重复发生可累计/更新时间；恢复和再次发生如何重开应有断言，不能无限刷屏或永远吞掉第二次故障。

事件落库是主流程，Webhook为可选投递。投递使用独立持久记录与不可变目标修订快照，记录待投递/投递中/成功/失败、次数、下次重试、限长错误；有界指数退避、过期/保留与手动重试。只承诺有界至少一次尝试，可能重复且不保证最终送达，消息携带稳定eventId供接收方去重。事件保留有界且截断可见，不能无限保留未读；通知失败不递归发送自身。

Webhook首版 HTTPS且默认禁用。未授权私网/回环拒绝，家庭内网接收器只能通过独立显式可信目标授权；链路本地/元数据/危险保留地址始终拒绝。按每次连接实际解析地址核验，处理DNS变更，拒绝所有重定向且不继承环境代理。URL凭据/令牌保持write-only，测试投递同策略；响应体、错误和导出脱敏，设置超时/大小/并发预算。关闭后旧队列disabled，重启/再启用不重投旧项；恢复备份用可操作的CLI/配置先禁用通知，核对后再启用。

S02/S03提供原业务结果与日志；S04负责在基础接口就绪后追加生产者和备份失败全链路联调。S02/S03主体及整项完成均不等待S04，S04基础存储不依赖生产者；这样没有相互完成依赖。S09–S12复用同一事件中心。

## 5. S05/S06：文件、作品与元数据

拟议 `works`（电影/剧集）、`seasons/episodes`、`work_items`（文件关系）与字段来源/人工锁定记录。集与文件允许多对多或等价明确映射，以支持多集文件和多版本文件；单一 nullable episode_id 不能冒充完整需求。唯一约束、归组置信度与手工调整优先级在 S05 的第一 PR 明确。

初始迁移不强制批量归组、不做同步全盘 hash；不确定识别保留“未归组”，同名不同年份/版本不静默合并。作品浏览与现有文件分页兼容，读写进度仍以原 item_id 为准；作品级已看聚合规则明确后再扩展，不静默改已有进度语义。

本地元数据优先只读读取受限目录内的 NFO/海报；必须通过各sidecar自身的下载/收集发布授权，视频可读不代表同目录sidecar已发布。XML禁外部实体/网络读取，限制字节、深度/节点/时间；图片限制格式/像素/解码预算，不接收活动SVG。字段记录来源及更新时间；人工锁定覆盖扫描来源，源NFO变更不能覆盖锁定；显式空值是有效覆盖。取消锁定后仍先预览再确认接管。

拟议人工海报上传经鉴权、大小/格式/像素限制存入持久资产区，数据库引用与文件发布使用可恢复状态，失败文件可按归属回收；图片衍生缓存和原始资产的删除策略分开。S06对资产备份清单、恢复和 S10引用检查做接入，不修改媒体源文件。

## 6. S07/S08：消费与管理

字幕首版支持明确授权的同目录 SRT/VTT，服务端按条目鉴权/根目录和发布清单安全打开，不能为读字幕放宽gate为同目录即允许；按受限字符集转换为纯净WebVTT，限制源大小/条目数/输出大小，不远程取字幕。输出纯文本，禁止HTML脚本和路径泄漏。对象URL/播放器状态随切换、关闭、卸载撤销，旧请求不能污染新媒体。

诊断来自有界异步 ffprobe 与浏览器能力探测，区分“容器/轨道信息”“可能支持”和“实际播放失败”；不给出保证能播放的虚假结论。首版不自动转码、改源或下载；转封装/音频转码须在真实样本证明需求后单建任务。

筛选拟议补充进度状态、多标签 AND/OR、元数据字段和稳定分页排序。未知值如何匹配、排序 tie-breaker、筛选保存的版本与字段校验要明确。人工已看单独存覆盖状态，不伪造进度。批量首轮最多200个显式ID，短事务全有或全无，冲突列出需刷新ID；不能用未加载项目冒充“全选全部”。

重关联流程先预览再确认：只处理旧文件已失联且目标未索引的item，验证配置内同类型库/目标根、发布授权、文件类型、存在性和活动引用；成功保留原item_id及状态/作品关联，使旧技术来源缓存失效但不删人工锁定值。目标已被另一个条目索引时拒绝并显示冲突，不静默覆盖、合并或删除进度。指纹只能辅助建议，不能自动合并。

## 7. S09–S11：导入、容量与规则

自动入库以显式授权的“可信来源完成目录→已有目标库”映射为单位，首轮只register且默认关闭，只处理启用后新产物，历史另预览确认。稳定性检测只是必要候选条件，不是完成证明；禁止将活动staging或未知受管complete当完成根，不移动/删除。抽取共享应用服务复用preview/register/任务状态、发布证明和真实扫描覆盖核验，不增加绕过原门禁的直接插表路径。

去重键由映射、规范化源身份与稳定文件版本组成，具体摘要预算在 S09确定。重启/重复扫描/目录掉线不能重复复制或把未完成视为成功；未知外部操作等待对账。配置更新/暂停/取消与正在执行任务的关系需显式处理。

容量按媒体根、共享卷、下载暂存、发布产物、缓存、资产、备份、组件卷分别标识，无法读取的远端卷显示未知；同卷不得简单相加可用空间。低水位告警复用事件中心，带去抖与恢复阈值。worker的10000上限同时影响提交与启动恢复；冷热UUID查询保留requestHash/完整私密请求/最终响应/发布清单和RSS去重，冷损坏失败封闭，不能重新当新ID获取。首轮app保留gate依赖的任务主行/files；不得先删原行再补凭证读取。归档只减少热压力，不等于删除媒体释放空间。

清理首版默认只预览：只列本应用拥有且可证明无活动/做种/索引/凭证引用的派生或失败暂存，执行使用有期限精确清单，复核归属与引用，不重新扫描扩大范围；取消或失败不得删除原片、人工资产、组件数据卷、未知目录。不可安全证明则转人工。

规则模板包装已有RSS/规则执行器；解释预览与真实执行使用同一判定函数，预览无外部副作用。缺集视图标注集数信息来源和未知状态，外部列表不得被描述为版权/完整性保证；不同时引入跨来源自动替换/画质升级策略。

## 8. S12：组件维护

保持四固定组件白名单、固定模板/镜像、私密执行端、归属标签、nonce/请求验证及 Desktop参数契约。先增加实际版本/目标版本/健康差异与单组件停启/维护，再实现受控升级。未知版本显示未知，不把配置值当实际探测结果。

升级必须有源/目标固定引用、架构/宿主/卷与配置兼容、实际上游迁移说明、停机预期、恢复点和隔离验证。实施时查官方资料并实测，不在本规划锁定未来最新版。执行途中崩溃保留步骤与未知状态，先对账再操作；不能复用“重试部署”冒充可逆升级。

保数据卸载只移除可证明属于本应用的服务/容器，不自动删除卷、下载、媒体或人工资产；若恢复依赖数据库/配置版本匹配则明确说明。不具备可验证逆向迁移时仅提供备份恢复路径，不承诺一键回滚。

## 9. 检查与发布记录

每项验收记录拆为“本轮实际执行”“历史参考”“目标未验”。本机 fixture、交叉编译、稀疏大文件Range只能证明各自断言；真实Docker/组件、NAS挂载与ACL、播放器兼容/资源峰值和完整恢复需要实际环境证据。

执行命令经 `python -B scripts/project_env.py -- ...`。浏览器/MCP若要启动需预先继承同样环境，不对已运行进程作虚假隔离承诺。只在变更触发时运行对应领域脚本，纯文档规划不重复全项目构建。
