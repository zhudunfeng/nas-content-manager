# 在平台部署资源组件

在“资源收集 → 来源 → 添加来源”选择 MoviePilot、AutoBangumi、Sonarr 或 Radarr，再选择“在此部署”。确认目录访问范围后部署，页面会显示真实镜像层进度；关页和刷新不会取消已接受的任务。同一请求重试会恢复原任务。

流程为：**部署 → 完成组件首次配置 → 输入 API 凭据并检测 → 使用平台管理**。容器已运行时显示“待首次配置”，只有原 API 连接检测通过才显示应用已连接。MoviePilot 的搜索、订阅、下载编排、整理、刮削和媒体库索引刷新沿用现有集成能力。

## 启用一次部署能力

Linux NAS 使用新版 `compose.engines.yaml`，按 [引擎部署](engines.md) 更新应用和私有助手。该覆盖文件启用 `ENGINE_COLLECTION_ENABLED=true`，预挂组件资源根；仅启动助手不会安装四个组件。只使用基础 Compose 或原生程序时，仍可连接已有组件。

Windows 使用带 **v3 镜像清单**和 `compose.desktop.components.yaml` 的 Docker 完整模式发布包。v3 可以附带网页/远程获取执行端，也可以只有应用和助手。旧 v1/v2 清单保留原角色和挂载，需要更新完整包才可从页面部署；它们仍能连接已有外部服务。Docker Desktop/WSL 由用户预先安装并启动，平台不会修改操作系统安装。

组件安装不改动已有实例。名称或卷归属冲突会停止当前操作，页面提供诊断；不会覆盖、删除或自动接管外来容器。

## 首次配置

管理入口只绑定 **Docker 宿主的 127.0.0.1**。Windows 本机浏览器可以直接打开；NAS 远程浏览器需先建立 SSH 转发，不能将工作站 localhost 当成 NAS。

| 组件 | 固定版本 | 宿主回环端口 | 首次操作 |
| --- | --- | --- | --- |
| MoviePilot | 3.2.8 | 19130 | 在初始化页面创建管理员及 API Key；配置站点、下载器、目录和媒体服务器 |
| AutoBangumi | 4.0.0 | 19132 | 默认 `admin/adminadmin`，首次登录修改密码；配置下载器，创建 API scope 令牌 |
| Sonarr | 4.0.20.3014 | 19133 | 完成 Web 鉴权设置，配置索引器/下载器/目录，从设置取得 API Key |
| Radarr | 7.0.3.10918 | 19134 | 完成 Web 鉴权设置，配置索引器/下载器/目录，从设置取得 API Key |

例如从工作站访问 NAS 上的 MoviePilot：

```sh
# nas-user和nas-host替换为实际SSH账号与NAS主机；保持此进程运行。
ssh -N -L 19130:127.0.0.1:19130 nas-user@nas-host
```

然后访问工作站 `http://127.0.0.1:19130`。其他组件使用表中相同本地/远端端口。所有组件仅公开各自 Web 配置入口，助手控制面仍只有私有 Unix socket。

首次配置后回平台使用“连接此组件”，填写自己的 API 凭据，再保存并检测。内部服务地址供平台访问，与浏览器入口不同；凭据只写入原有私密连接存储，不从部署卷、容器日志或浏览器缓存提取。固定摘要决定安装内容，组件内更新或插件可能改变运行版本，API 检测仍核对实际版本。

## 下载、整理和入库

四组件各有独立私密配置卷，共享以下两个明确授权的数据挂载：

| 组件内路径 | 用途 | 平台视图 |
| --- | --- | --- |
| `/downloads` | 现有受管下载目录；由用户在组件中配置实际下载器和目录 | 平台原下载发布门禁保持生效 |
| `/data` | 独立组件资源根；整理到 `/data/library/<组件>` | 只读 `/collection-media`，仅 `library` 子树可登记 |

例如 MoviePilot 的整理目标为 `/data/library/moviepilot`，平台完成目录选择 `/collection-media/library` 根及子目录 `moviepilot`。组件下载或整理成功后，仍需在平台预览并执行完成目录导入，才能生成本地媒体条目。

平台不自动填写 qB 账号、不向现有下载器添加配置、不接管原下载任务。两数据挂载之间采用**复制整理**，跨卷不支持硬链接或原子移动；不要将 staging 或仍在下载的目录当成完成目录。原始 Windows/NAS 媒体库继续只读，组件不会获得该媒体盘写挂载。

## 恢复、停止和备份

部署中断后保留原任务编号与请求键，恢复连接可继续查看或重试失败步骤。停止的受管组件可显式启动，启动不会重新安装缺失容器；HTTP 尚未响应时显示启动中或失败原因，不能推断 API 已配置。

Windows“停止完整模式”先核验并停止本安装 qB/Jackett 及四个资源组件，再停应用、助手和可选获取服务。Linux 手动停栈前执行 [引擎文档](engines.md) 中的 helper `stop-all`。过程可能等待数分钟，失败会保留应用/助手供排查，容器、镜像和数据卷全部保留。

备份应包含 app 数据、helper state（包括安装身份和卷授权）、原下载与连接卷、`collection-media`、四组件各自配置/缓存/数据库卷。组件凭据和数据库需按敏感数据保存，停机后备份并原身份恢复；网页主数据库备份不包含这些文件。本轮不提供卸载、清库、任意镜像安装或真实站点账号配置。
