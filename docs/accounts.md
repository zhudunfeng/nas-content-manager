# 管理员凭据与离线恢复

系统当前采用单管理员模型。能够登录时，进入设置中的“账号安全”修改密码、查看当前会话或退出其他会话；遗忘密码时，使用同版本主程序的停机维护命令。

## 在线账号安全

- 修改密码需要当前密码与新密码。旧弱密码或中文密码仍按原值校验，可升级为符合新规则的密码。
- 改密成功会撤销全部旧会话并退出当前页面。使用新密码重新登录；已经准入的媒体传输可能完成，后续旧 Cookie 请求会被拒绝。
- 会话列表单独固定当前会话，其他会话按公开随机编号分页；这不是最近登录排序。历史创建时间可能未知，浏览器与系统类别只是显示提示。
- 退出其他会话需要再次输入当前密码，保留实际当前会话。返回数量是删除的会话记录数，可能包含过期记录，不能视为活跃设备数。
- 再认证受账号与会话共享预算限制；遇到等待提示按 `Retry-After` 稍后重试。网络结果未知时，不自动重复提交改密或撤销请求。

精确 HTTP 字段、错误码、分页与限流规则见 [API 的 Account security 部分](api.md#account-security)。

## 停机离线重置

1. 找到该实例实际使用的数据目录，确认其中已有普通文件 `library.db`，并保留与数据库版本匹配的安全备份。不要针对媒体目录或新建空目录执行。
2. 正常停止使用同一数据目录的服务或桌面实例。等待退出完成；维护工具复用原实例的操作系统独占锁，不能强制破锁，也不会停止占用者。
3. 使用与数据库版本匹配的主服务程序执行命令。默认从真实终端无回显输入两次新密码。

Windows 示例（在主程序所在目录）：

```powershell
.\nas.exe account reset-password --data-dir "E:\NAS Data"
```

Linux 命令形式：

```sh
./nas account reset-password --data-dir "/srv/nas-data"
```

Linux 命令形式已交叉编译检查；真实 Linux 终端、`flock`、权限和 NAS 文件系统仍需在目标环境验收。

4. 等待退出码 `0` 和完成提示，再按原配置启动服务。原密码与全部旧 Cookie 均已失效，使用新密码重新登录。

仅下面的精确帮助命令可以在不打开目录、锁或数据库的情况下执行：

```text
nas account reset-password --help
```

命令仅接受空格分隔的 `--data-dir <目录>` 及可选的 `--password-stdin`。不支持 `--data-dir=<目录>`、重复选项、额外位置参数或密码参数。无参数启动原服务；任何未知带参命令都会失败，不会误启动服务。

### 密码与输入规则

新密码必须为 **10–72 个 ASCII 可打印非空白字符（U+0021–U+007E）**，同时包含大写字母、小写字母、数字和 ASCII 标点四类。中文、全角、空格、控制字符和 emoji 均不接受。输入不 trim，也不截断。

默认交互要求真实终端，两个提示均无回显。可以使用退格修改；每次提示最多接收 1024 个非行结束原始字节（包括退格）。非法字符或超出预算后，即使再退格也会失败，需要重新执行。两次不匹配、提示失败、终端恢复失败均不写入账号。Ctrl+C、系统取消或 Ctrl+D 可取消输入，终端恢复后退出。

工具不从命令行参数或环境变量读取密码。不要把真实密码写入命令历史、脚本正文或示例命令。自动化场景只能由受控秘密生产者通过私有管道提供标准输入，并显式加入 `--password-stdin`；不要通过 shell 的字符串回显命令拼装真实密码。

`--password-stdin` 只接受重定向输入，真实终端使用该选项会拒绝。生产者须关闭管道提供 EOF，输入为单个密码，可带一个最终 LF 或 CRLF。最多读取 75 字节（含超限哨兵），合法密码仍最多 72 字节；内部换行、额外空行、单独最终 CR、超长尾部均拒绝，不能只取第一行或前 72 字节。没有显式选项的管道输入也会拒绝。

### 数据与版本边界

离线工具只打开已有本地目录中的普通 `library.db`，拒绝数据库链接、目录、缺库及 UNC 数据路径；目录别名规范化后竞争相同实例锁。锁只协调遵守本项目协议的实例，不替代对同权限第三方修改文件的访问控制。

当前维护支持**显式限定为 schema 5 和 6**，不随正常启动版本常量自动扩大。低于 5 的数据库须先用匹配应用正常迁移并停服，再执行维护；高于 6 的版本须使用匹配维护程序。短事务内要求实际 `user_version` 与预检时完全一致，即使 5 与 6 都受支持，输入期间发生双向版本变化也会拒绝。当前快照下载校验器只接受头版本 6，与此维护支持集不同。维护入口不迁移数据库、不创建管理员，不启动 HTTP、媒体扫描、任务恢复或缓存清理，也不需要媒体根、FFmpeg 或网页目录。

工具校验账号表及相关约束、唯一有效 ID=1 管理员与非溢出修订；现有 bcrypt 摘要的版本、精确长度、两位数字成本与编码字符也必须有效。损坏摘要会拒绝维护，不会重建账号。在短事务内重新核对结构和凭据快照，成功只替换密码摘要、推进凭据修订并删除该账号全部会话；媒体、个人状态、作业、外部动作、缓存、已有备份域记录及 pending 文件均保留，也不准备备份根或执行备份对账。输入与 bcrypt 在写事务外完成，数据库关闭后才释放目录租约。

### 退出码与失败处理

| 退出码 | 含义与处理 |
| --- | --- |
| `0` | 已成功提交并完成清理，或精确帮助输出成功。重置后正常启动并用新密码登录。 |
| `2` | 命令或选项用法错误；按固定帮助修正，不会回显未知参数。 |
| `130` | 提交前的纯取消；账号未修改。清理失败不会伪装成此退出码。 |
| `1` | 前置检查、密码输入、权限、存储、终端恢复或清理失败；根据固定中文原因处理。 |

目录占用时应正常停服；权限不足时检查该实例运行身份对数据目录、锁及数据库的权限。工具不会强制破锁、杀进程、更改 ACL 或升级权限。

若明确提示“密码已重置，但维护清理失败”，提交已经完成，不能把密码视为仍是旧值。若提示“事务结果未确认”，须先核对账号和存储状态，**不能自动重试**。输出失败也可能发生在提交后；不要仅因退出码 `1` 就断定未修改。保留现有数据，确认实例已停止，再通过匹配程序的正常启动及登录核对结果。

恢复整库备份可能恢复备份中的旧凭据与旧会话。只使用匹配 schema 的备份，并按恢复方案再次撤销旧会话；不要通过代码降级或手工编辑数据库绕过版本与修订校验。

## 开发验证

以下命令只在仓库中使用，要求显式指定已构建的主服务产物及 `.runtime/verify` 下尚不存在的运行根：

```powershell
python -B scripts/project_env.py -- python -B scripts/verify_account_offline.py --binary .runtime/bin/s02-3-stable/nas.exe --root .runtime/verify/account-offline-new
python -B scripts/project_env.py -- python -B scripts/verify_account.py --binary .runtime/bin/s02-3-stable/nas.exe --offline --root .runtime/verify/account-combined-new
```

单独离线结果写入 `result.json`、`assertions.json`，使用 `passed`、`offlineCLI`、`assertions` 与 `evidence` 判断。组合模式保留在线断言，在 `offline/` 单独写离线证据；顶层 `onlineAssertions + offlineAssertions = assertions`，且 `offlineVerification.requested/passed`、`offlineCLI` 均为 true 才代表完整账号组合通过。默认不加 `--offline` 只运行在线验证。

在线验证另在 `oversized/oversized-result.json` 保存账号大正文的状态与耗时，包括一百次关闭连接请求、分片正文、巨大声明但停滞、Expect、未知长度、提前 EOF 和精确 64 KiB 边界。传输重置会直接使本组失败，不能通过客户端重试记成 413；本机通过也不承诺任意网络下的响应绝对送达。

离线验证器在持久化脱敏前检查内存中的原始 stdout/stderr；Windows 真实专属 Console 另采可见 viewport 检查无秘密回显，并记录模式恢复。ACL 仅当 `evidence.actualPermissionDenial=true` 时才有普通写句柄实际被拒绝及原 ACL 恢复的证据。Windows 无文件符号链接特权时，`databaseLinkFixture` 明确记录目录 Junction 替代夹具，不能据此声称文件符号链接已实测。Linux 交叉编译不构成 Linux/NAS 的锁、终端、权限或性能验收。
